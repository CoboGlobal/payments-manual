本文介绍收款、退款和资金转出过程中涉及到的所有 Webhook 事件以及状态变更流程。

## Webhook 事件

### 交易负载字段

下表列出所有 `payment.transaction.*` 事件负载中包含的基础字段。在一些场景下，部分字段可能不会返回。

| 字段 | 类型 | 是否必填 | 说明 |
|:-----|:-----|:---------|:-----|
| `transaction_id` | string (UUID) | 是 | 交易 ID。 |
| `cobo_id` | string | 否 | 用于追踪交易的 Cobo ID。 |
| `request_id` | string | 否 | 用于追踪交易请求的请求 ID。 |
| `wallet_id` | string | 是 | 充币交易中为目标钱包 ID；其他类型为源钱包 ID。 |
| `type` | string | 否 | 交易类型。 |
| `status` | string | 是 | 交易状态。 |
| `sub_status` | string | 否 | 交易子状态。 |
| `failed_reason` | string | 否 | 交易失败原因（仅适用于审批和签名失败）。 |
| `chain_id` | string | 否 | 链 ID。 |
| `token_id` | string | 否 | 代币 ID。 |
| `asset_id` | string | 否 | 资产 ID（仅限交易所钱包）。 |
| `transaction_hash` | string | 否 | 交易哈希。 |
| `source` | object | 是 | 交易来源。 |
| `destination` | object | 是 | 交易目标。 |
| `result` | object | 否 | 交易结果。 |
| `fee` | object | 否 | 交易手续费。 |
| `initiator` | string | 否 | 交易发起者。 |
| `initiator_type` | string | 是 | 发起者类型。 |
| `confirmed_num` | integer | 否 | 已收到的确认数。 |
| `confirming_threshold` | integer | 否 | 所需最低确认数。 |
| `block_info` | object | 否 | 区块信息。 |
| `raw_tx_info` | object | 否 | 原始交易信息。 |
| `replacement` | object | 否 | 替换交易信息。 |
| `category` | array | 否 | 自定义交易分类。 |
| `description` | string | 否 | 交易描述。 |
| `is_loop` | boolean | 否 | 是否为 Cobo Loop 转账。 |
| `cobo_category` | array | 否 | Cobo 定义的交易分类。 |
| `extra` | array | 否 | 结构化的业务专属附加信息。 |
| `fueling_info` | object | 否 | 加油信息。 |
| `created_timestamp` | integer (int64) | 是 | 创建时间，Unix 时间戳（毫秒）。 |
| `updated_timestamp` | integer (int64) | 是 | 最后更新时间，Unix 时间戳（毫秒）。 |

每个交易事件还包含事件内容列中列出的 Payment 专属字段。

### **2. 资金转出相关**

| 功能场景 | 事件名称 | 触发条件 | 事件内容 |
| :------- | :------- | :------- | :------- |
| 退款 | `payment.refund.status.updated` | 仅推送以下退款状态：<br />- `Pending`：确认退款链接并创建退款单。<br />- `Completed`：所有退款交易均成功。<br />- `PartiallyCompleted`：同时存在成功交易和失败或缺失的转账。<br />- `Failed`：所有退款交易均失败。<br />`Processing` 和 `PendingConfirmation` 不会触发该 Webhook。 | 该负载包含以下字段：<br />- `refund_id`（必填）：退款订单 ID。<br />- `request_id`（选填）：创建退款时您提供的请求 ID。<br />- `order_id`（选填）：该退款对应的收款订单 ID。<br />- `merchant_id`（选填）：商户 ID。<br />- `token_id`（必填）：用于退款的加密货币 ID。<br />- `chain_id`（必填）：区块链网络 ID。<br />- `amount`（必填）：该退款需退还的加密货币金额。<br />- `to_address`（必填）：收款钱包地址。<br />- `status`（必填）：推送的退款状态，可能的值：`Pending`、`Completed`、`PartiallyCompleted`、`Failed`。<br />- `failed_reason`（选填）：退款失败原因。<br />- `refund_type`（选填）：资金来源，可能的值：`Merchant`、`Psp`。<br />- `created_timestamp`（必填）：创建时间，Unix 时间戳（秒）。<br />- `updated_timestamp`（必填）：最后更新时间，Unix 时间戳（秒）。<br />- `initiator`（选填）：退款请求发起者。<br />- `transactions`（选填）：与该退款关联的支付交易数组。<br />- `charge_merchant_fee`（选填）：是否向商户收取开发者手续费。<br />- `merchant_fee_amount`（选填）：向商户收取的开发者手续费金额。<br />- `merchant_fee_token_id`（选填）：开发者手续费使用的加密货币 ID。<br /><br />完整字段说明请参考 [Get refund order information](/payments/en/api-references/payment/get-refund-order-information)。 |
| 单目的地资金转出 | `payment.payout.status.updated` | 资金转出达到终态结果时推送。<br />待处理交易不会触发该 Webhook。`Pending`、`Preparing` 和 `Transferring` 是不触发推送的模型或详情状态，`WaitingOTC` 状态变更也会被抑制。 | 该负载包含以下字段：<br />- `payout_id`（必填）：资金转出 ID。<br />- `request_id`（必填）：创建资金转出时您提供的请求 ID。<br />- `payout_channel`（必填）：转出渠道，可能的值：`Crypto`、`OffRamp`。<br />- `source_account`（选填）：转出来源账户。<br />- `payout_items`（选填）：转出条目数组。<br />- `recipient_info`（选填）：收款人信息。<br />- `initiator`（选填）：资金转出请求发起者。<br />- `actual_payout_amount`（选填）：实际到账金额。<br />- `commission_fees`（选填）：该笔转出的佣金费用数组。<br />- `remark`（选填）：备注信息。<br />- `status`（必填）：该笔资金转出推送的终态结果。<br />- `created_timestamp`（必填）：创建时间，Unix 时间戳（秒）。<br />- `updated_timestamp`（必填）：最后更新时间，Unix 时间戳（秒）。<br />- `transactions`（选填）：与该笔转出关联的支付交易数组。<br /><br />完整字段说明请参考 [Get payout information](/payments/en/api-references/payment/get-payout-information)。 |
| 批量下发加密货币 | `payment.bulk_send.status.updated` | 处理结束时推送：<br />- `Completed`：所有条目均完成。<br />- `PartiallyCompleted`：部分条目完成，其他条目失败。<br />- `Failed`：没有条目完成，或审批被拒绝或撤销。<br />`Pending`、`Validating` 和 `Transferring` 是中间模型状态，不是最终推送节点。 | 该负载包含以下字段：<br />- `bulk_send_id`（必填）：批量下发 ID。<br />- `request_id`（选填）：创建批量下发时您提供的请求 ID。<br />- `source_account`（必填）：转出来源账户。<br />- `execution_mode`（必填）：执行模式。<br />- `status`（必填）：当前批量下发状态。<br />- `commission_fee`（选填）：佣金费用详情。<br />- `failed_reason`（选填）：批量下发失败原因。<br />- `created_timestamp`（必填）：创建时间，Unix 时间戳（秒）。<br />- `updated_timestamp`（必填）：最后更新时间，Unix 时间戳（秒）。<br /><br />完整字段说明请参考 [Get bulk send information](/payments/en/api-references/payment/get-bulk-send-information)。 |
| 账户余额 | `payment.account.balance.updated` | Payment 账户某币种的每条已持久化可用余额变动记录都会触发。 | 该负载包含以下字段：<br />- `source_account`（必填）：余额变动的来源账户。商户账户为商户 ID；开发者账户为 `developer`。<br />- `source_id`（必填）：余额变动的来源 ID。<br />- `source_type`（必填）：余额变动的来源类型，例如 `OrderIn`、`LatePayment`、`TopUp`、`RefundOut`、`Payout`、`Allocation`、`SettlementNetwork`、`BulkSend` 和 `Init`；此列表并非完整列表。<br />- `token_id`（必填）：币种 ID。<br />- `amount`（必填）/ `amount_raw`（必填）：余额变动金额，分别为保留两位小数和按币种精度表示。<br />- `balance_before` / `balance_before_raw`（必填）：变动前的账户余额。<br />- `balance_after` / `balance_after_raw`（必填）：变动后的账户余额。<br />- `flow_direction`（必填）：余额变动方向，可能的值：`in`、`out`。<br />- `update_time`（必填）：余额更新时间，Unix 时间戳（秒）。 |

## 提示

为了保证数据的绝对准确性并避免并发冲突，Webhook 消息体中不会包含实时余额变动和详细扣费信息。如果您存在以下使用场景，请参考下列提示说明：

- 若需要根据 Webhook 通知及时更新余额，您可以：在接收到 Webhook 时，立即调用 [List merchant balances](/payments/en/api-references/payment/list-merchant-balances) 或 [Get developer balances](/payments/en/api-references/payment/get-developer-balance) 接口获得准确的余额信息，再进行内部记账。
- 若需要及时知道 Webhook 所指交易引发的扣费信息，以便于关联交易和扣费进行对账，您可以：使用对应的查询交易信息接口和 [Generate reports](/payments/en/api-references/payment/generate-reports) 获取扣费报表，来做数据的核对。
- 若需要及时知道 Webhook 所指交易引发的 Fee Station 余额的变动情况，保证后续不因 Fee Station 余额不足而影响业务，您可以：定期调用 [List Fee Station token balance](https://www.cobo.com/developers/v2/api-references/feestation/list-fee-station-token-balances) 查询 Fee Station 余额，并根据业务的消耗频率做内部报警策略，避免欠费影响正常业务运行。
