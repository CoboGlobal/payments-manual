KYC 要求用于在您使用 POBO 前识别付款主体。`Submit merchant KYC` 请求在各支持国家和地区使用相同字段名，但必需附件 `file_type`、主证件类型和香港地址校验规则因国家和地区而异。

本指南覆盖 `HKG`、`TWN`、`MYS`、`PHL`、`IDN`、`VNM`、`THA`、`SGP`、`GBR` 和 `MEX` 的 KYC 国家和地区差异。

## 前提条件

- 在提交 KYC 信息前，准备付款主体的公司文件或个人身份证明文件。
- 通过 [Upload file v2](/payments/en/api-references/payment/upload-file-v2) 上传每个必需文件，并在 KYC 请求中使用返回的 `file_id`。
- 通过 [Submit merchant KYC](/payments/en/api-references/payment/submit-merchant-kyc) 提交 KYC 信息。
- 如需查看完整 POBO 流程，请参考 [POBO（全球付款）](/payments/cn/guides/pobo)。

## 共享请求结构

KYC 请求在所有支持国家和地区使用一致的 JSON key。国家和地区差异体现在可接受取值和必需附件，而不是字段名。

| 范围 | 字段 |
| --- | --- |
| 公司顶层请求 | `merchant_type`、`country`、`merchant_id`、`industry`、`company_info` |
| 个人顶层请求 | `merchant_type`、`country`、`merchant_id`、`industry`、`individual_info` |
| 地址对象 | `country`、`state`、`city`、`postcode`、`line1` |
| 人员信息 | `name`、`name_en`、`id_number`、`date_of_birth`、`issue_date`、`expiration_date`、`residential_address`、`attachments` |

## 公司 KYC 要求

对于公司 KYC，将 `merchant_type` 设置为 `B2B`，并提供 `company_info`。请勿在同一请求中提供 `individual_info`。

### HKG 基准字段

| 字段 | 要求 |
| --- | --- |
| `company_type` | 必传。使用 `Limited Company`。 |
| `listed` | 必传。表示公司是否为上市公司。 |
| `identify_no` | 必传。公司注册号或识别号。 |
| `company_name` | 必传。本地公司名称。 |
| `company_name_en` | 必传。英文公司名称。 |
| `establish_date` | 必传。公司成立日期，格式为 `YYYYMMDD`。 |
| `commencement_date` | 必传。开业日期，格式为 `YYYYMMDD`。 |
| `valid_period` | 必传。有效期日期，格式为 `YYYYMMDD`。 |
| `operation_address` | 必传。包含 `country`、`state`、`city`、`postcode` 和 `line1`。 |
| `register_address` | 必传。包含 `country`、`state`、`city`、`postcode` 和 `line1`。 |
| `legal_info` | 必传。法人信息，使用 PersonInfo 结构。 |
| `ubo_infos` | 必传。至少包含一个 UBO PersonInfo 对象。 |
| `online_store_url` | 必传，除非改为提供业务文件。 |
| `attachments` | 必传。公司附件列表。 |

### 公司附件要求

| 国家或地区 | 公司附件 `file_type` | 法人和 UBO 主证件 | 特殊规则 |
| --- | --- | --- | --- |
| `HKG` | `CI`、`BR`、`NNC1`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `FIC` | 基准国家或地区。 |
| `TWN` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `MYS` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `PHL` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `IDN` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `VNM` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `THA` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `SGP` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | `company_name_en` 必须包含 `Pte Ltd` 后缀。 |
| `GBR` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| `MEX` | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |

对于非中国大陆人员，提供 `name`、`name_en`、`id_number`、`date_of_birth`、`issue_date`、`expiration_date`、`residential_address` 和 `attachments`。如使用中国大陆身份证，请同时提供 `PRC_ID_Emblem` 和 `PRC_ID_Portrait`。

## 个人 KYC 要求

对于个人 KYC，将 `merchant_type` 设置为 `B2C`，并提供 `individual_info`。

### HKG 基准字段

| 字段 | 要求 |
| --- | --- |
| `name` | 必传。本地语言个人姓名。 |
| `name_en` | 必传。英文个人姓名。 |
| `id_number` | 必传。身份证明文件号码。 |
| `date_of_birth` | 必传。出生日期，格式为 `YYYYMMDD`。 |
| `issue_date` | 必传。身份证明文件签发日期，格式为 `YYYYMMDD`。 |
| `expiration_date` | 必传。身份证明文件到期日期，格式为 `YYYYMMDD`。 |
| `residential_address` | 必传。包含 `country`、`state`、`city`、`postcode` 和 `line1`。对于 `HKG`，`city` 必须使用受支持的香港地区值。 |
| `attachments` | 必传。包含主证件、`ID_Hand` 和 `POA`。 |

### 个人国家和地区差异

| 国家或地区 | 主证件 `file_type` | 姓名语言 | `city` 校验 | 其他必需附件 |
| --- | --- | --- | --- | --- |
| `HKG` | `HK_PID` 或 `FIC`；香港居民请勿使用 `PP`。 | 中文 | 必须使用受支持的香港地区中文或英文值。 | `ID_Hand`、`POA` |
| `PHL` | `FIC`；也接受 `PP`。请勿使用 `HK_PID`。 | 英文 | 使用当地英文城市值。不适用香港地区列表。 | `ID_Hand`、`POA` |
| `TWN`、`MYS`、`IDN`、`VNM`、`THA`、`SGP`、`GBR`、`MEX` | `PP`；也接受 `FIC`。请勿使用 `HK_PID`。 | 英文 | 使用当地英文城市值。不适用香港地区列表。 | `ID_Hand`、`POA` |

## 下一步

付款主体通过 KYC 审核后，创建收款银行账户转出目的地。如需查看 SWIFT 国家和地区差异，请参考[各国家和地区银行账户要求](/payments/cn/guides/bank-account-requirements-by-country)。
