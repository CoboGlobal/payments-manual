付款主体在发起 POBO 付款前需通过 KYC 审核。提交时 [Submit merchant KYC](/payments/en/api-references/payment/submit-merchant-kyc) 的字段名在所有支持的国家和地区都相同，只有三处会随主体所在国家和地区变化：必需的附件类型（`file_type`）、可用的主证件类型，以及中国香港的地址取值校验。

本指南逐个列出这三处差异，覆盖中国香港（`HKG`）、中国台湾（`TWN`）、马来西亚（`MYS`）、菲律宾（`PHL`）、印度尼西亚（`IDN`）、越南（`VNM`）、泰国（`THA`）、新加坡（`SGP`）、英国（`GBR`）、墨西哥（`MEX`）。

## 前提条件

- 在提交 KYC 信息前，准备付款主体的公司文件或个人身份证明文件。
- 通过 [Upload file v2](/payments/en/api-references/payment/upload-file-v2) 上传每个必需文件，并在 KYC 请求中使用返回的 `file_id`。
- 通过 [Submit merchant KYC](/payments/en/api-references/payment/submit-merchant-kyc) 提交 KYC 信息。
- 如需查看完整 POBO 流程，请参考 [POBO（全球付款）](/payments/cn/guides/pobo)。

## 共享请求结构

KYC 请求在所有支持国家和地区使用一致的 JSON key。国家和地区差异体现在可接受取值和必需附件，而不是字段名。

`merchant_type` 与实体类型是两个独立的维度，不要互相推导：

- `merchant_type` 描述经营模式：`B2B` 面向企业，`B2C` 面向消费者。
- 实体类型由请求中提供的对象决定：企业提供 `company_info`，个人提供 `individual_info`。同一请求中只提供其中一个。

因此，企业主体一律提供 `company_info`，`merchant_type` 则取决于其客户类型：客户为消费者取 `B2C`，客户为企业取 `B2B`。

| 范围 | 字段 |
| --- | --- |
| 公司顶层请求 | `merchant_type`、`country`、`merchant_id`、`industry`、`company_info` |
| 个人顶层请求 | `merchant_type`、`country`、`merchant_id`、`industry`、`individual_info` |
| 地址对象 | `country`、`state`、`city`、`postcode`、`line1` |
| 人员信息 | `name`、`name_en`、`id_number`、`date_of_birth`、`issue_date`、`expiration_date`、`residential_address`、`attachments` |

## 公司 KYC 要求

对于公司 KYC，提供 `company_info`，并按经营模式将 `merchant_type` 设置为 `B2B` 或 `B2C`。请勿在同一请求中提供 `individual_info`。

### B2B 与 B2C 企业的差异

两者的国家和地区维度要求完全相同：公司附件、法人与 UBO 主证件规则按下文各表执行，不随 `merchant_type` 变化。差异只有两处：

| 维度 | B2B 企业 | B2C 企业 |
| --- | --- | --- |
| `merchant_type` | `B2B` | `B2C` |
| `online_store_url` | 必传，除非改为提供公司附件 `BUSINESS_DOCUMENT` | 不按 B2B 规则校验，可不传 |
| 公司附件 `PLATFORM_SCREENSHOT` | 非必传 | 必传 |

### HKG 基准字段

| 字段 | 要求 |
| --- | --- |
| `company_type` | 必传。使用 `Limited Company`。 |
| `listed` | 必传。表示公司是否为上市公司。 |
| `identify_no` | 必传。公司注册号或识别号。 |
| `company_name` | 必传。本地公司名称。 |
| `company_name_en` | 必传。英文公司名称。 |
| `establish_date` | 必传。公司成立日期，格式为 `YYYYMMDD`。 |
| `commencement_date` | 必传。开业日期，格式为 `YYYYMMDD`。 |
| `valid_period` | 必传。有效期日期，格式为 `YYYYMMDD`。 |
| `operation_address` | 必传。包含 `country`、`state`、`city`、`postcode` 和 `line1`。 |
| `register_address` | 必传。包含 `country`、`state`、`city`、`postcode` 和 `line1`。 |
| `legal_info` | 必传。法人信息，使用 PersonInfo 结构。 |
| `ubo_infos` | 必传。至少包含一个 UBO PersonInfo 对象。 |
| `online_store_url` | 必传，除非改为提供业务文件。 |
| `attachments` | 必传。公司附件列表。 |

### 公司附件要求

下表的 `file_type` 是接口接受的附件类型，通过校验不代表合规审核一定通过。

| 国家或地区 | 公司附件 `file_type` | 法人和 UBO 主证件 | 特殊规则 |
| --- | --- | --- | --- |
| 中国香港（`HKG`） | `CI`、`BR`、`NNC1`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `FIC` | 基准国家或地区。 |
| 中国台湾（`TWN`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 马来西亚（`MYS`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 菲律宾（`PHL`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 印度尼西亚（`IDN`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 越南（`VNM`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 泰国（`THA`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 新加坡（`SGP`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | `company_name_en` 必须包含 `Pte Ltd` 后缀。 |
| 英国（`GBR`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |
| 墨西哥（`MEX`） | `CI`、`AOA`、`ANNUAL_RETURN`、`BAP`、`SSC` | `PP` | 请求字段与 `HKG` 一致；不提供 `BR` 和 `NNC1`。 |

对于非中国大陆人员，提供 `name`、`name_en`、`id_number`、`date_of_birth`、`issue_date`、`expiration_date`、`residential_address` 和 `attachments`。如使用中国大陆身份证，正反两面分别用 `PRC_ID_Emblem` 和 `PRC_ID_Portrait`。

## 个人 KYC 要求

对于个人 KYC，提供 `individual_info`，并将 `merchant_type` 设置为 `B2C`。个人商户面向消费者经营，因此取值为 `B2C`；但 `B2C` 本身不代表个人，面向消费者的企业同样使用 `B2C`（见上文差异表）。

### HKG 基准字段

| 字段 | 要求 |
| --- | --- |
| `name` | 必传。本地语言个人姓名。 |
| `name_en` | 必传。英文个人姓名。 |
| `id_number` | 必传。身份证明文件号码。 |
| `date_of_birth` | 必传。出生日期，格式为 `YYYYMMDD`。 |
| `issue_date` | 必传。身份证明文件签发日期，格式为 `YYYYMMDD`。 |
| `expiration_date` | 必传。身份证明文件到期日期，格式为 `YYYYMMDD`。长期有效、证件本身不印到期日的，填 `20991231`。 |
| `residential_address` | 必传。包含 `country`、`state`、`city`、`postcode` 和 `line1`。对于 `HKG`，`city` 必须取自下方的香港行政区列表。 |
| `attachments` | 必传。包含主证件的正反两面、`ID_Hand` 和 `POA`。正面用该证件对应的 `file_type`，反面用 `BACK`。 |

### 个人国家和地区差异

| 国家或地区 | 主证件 `file_type` | 姓名语言 | `city` 校验 | 其他必需附件 |
| --- | --- | --- | --- | --- |
| 中国香港（`HKG`） | `HK_PID` 或 `FIC`；香港居民请勿使用 `PP`。 | 中文 | 必须取自香港行政区列表，中英文均可。 | `ID_Hand`、`POA` |
| 菲律宾（`PHL`） | `FIC`；也接受 `PP`。请勿使用 `HK_PID`。 | 英文 | 使用当地英文城市名。 | `ID_Hand`、`POA` |
| 中国台湾（`TWN`）、马来西亚（`MYS`）、印度尼西亚（`IDN`）、越南（`VNM`）、泰国（`THA`）、新加坡（`SGP`）、英国（`GBR`）、墨西哥（`MEX`） | `PP`；也接受 `FIC`。请勿使用 `HK_PID`。 | 英文 | 使用当地英文城市名。 | `ID_Hand`、`POA` |

## 下一步

付款主体通过 KYC 审核后，创建收款银行账户转出目的地。如需查看 SWIFT 国家和地区差异，请参考[各国家和地区银行账户要求](/payments/cn/guides/bank-account-requirements-by-country)。
