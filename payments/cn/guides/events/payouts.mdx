本页的事件跟踪单笔资金转出或转账请求，无论是以加密货币结算，还是通过 Off-Ramp 结算到银行账户。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

批量转出请参见[批量下发事件](/payments/cn/guides/events/bulk-send)。

## 本页的事件

| 事件 | 通知什么 | 类型 |
| --- | --- | --- |
| [`payment.payout.updated`](#payment-payout-updated) | 一笔资金转出的结果：处理中、已完成、部分完成、失败，或被收款银行拒绝。 | 标准事件 |
| [`payment.bank_withdrawal.status.updated`](#payment-bank_withdrawal-status-updated) | 从您的某个虚拟账户提现法币到银行账户的状态变更。 | 标准事件 |

## `payment.payout.updated`

资金转出的主事件，以 `payout_id` 标识。

### 事件触发条件

**这笔转出的 `status` 每变化一次发一条事件。** 转出交易的中间变化（某笔完成、失败、获得 `tx_hash`）不单独通知。

| 什么时候会收到 | `status` | 是否终态 | 您该做什么 |
| --- | --- | --- | --- |
| 转出请求被受理 | `Pending` | 否 | 记录本次转出，不要重复提交。 |
| 开始准备资金（归集、跨链兑换、扣佣金） | `Preparing` | 否 | 等待。 |
| 开始执行转出交易 | `Transferring` | 否 | 等待。即使部分转出交易已完成，也不能关闭付款。 |
| 全部转出成功 | `Completed` | 是 | 关闭本次转出。这表示 Cobo 已完成转账，不表示收款方平台已经入账。 |
| 有一部分没有成功 | `PartiallyCompleted` | 是 | 按 `failed_amounts` 的金额另建一笔转出补发，不要重复支付已成功的部分。 |
| 全部没有成功 | `Failed` | 是 | 读取 `failed_reason.code` 并处理，不要原地重试。 |
| 收款银行退回这笔 Off-Ramp 转账 | `RejectedByBank` | 否 | 记录一次被拒、通知运营核对收款账户信息，然后继续等这个 `payout_id` 的后续事件。 |

<Warning>
  **`RejectedByBank` 不是终态。** 银行拒绝后可以换一个收款账户重试，这笔转出会回到 `Transferring`，并可能最终 `Completed`。在它到达 `Completed`、`PartiallyCompleted` 或 `Failed` 之前：不要关闭付款或标记失败，不要另建一笔转出重发（会造成重复付款），也不要把此时的 `failed_reason` 当作最终结论。

  恢复时同一个 `status` 会再出现一次（例如第二条 `Transferring`）。**本地去重请用 `event_id`**，用 `payout_id` 加 `status` 会把恢复通知丢掉。
</Warning>

| `transactions.amount.amount` | `string` | 金额，十进制字符串。 |
| `transactions.amount.token_id` | `string` | 币种 ID。 |
| `transactions.amount.chain_id` | `string` | 链 ID。 |
| `transactions.tx_hash` | `string` | 链上交易哈希，广播前为 `null`。 |
| `transactions.result` | `string` | 该笔交易的结果：<br/>• `Completed`：已成功转出。<br/>• `Failed`：未成功，金额计入 `failed_amounts`。<br/>尚无结果时为 `null`。 |
| `transactions.failed_reason` | `object` | `result` 为 `Failed` 时有值，其余情况为 `null`。 |
| `transactions.failed_reason.code` | `string` | 失败原因代码，按它分支。取值见[失败原因](#失败原因)。 |
| `transactions.failed_reason.message` | `string` | 面向运营人员的说明，不要用于程序匹配。 |
| `failed_reason` | `object` | `status` 为 `Failed`、`RejectedByBank` 或 `PartiallyCompleted` 时有值，其余情况为 `null`。 |
| `failed_reason.code` | `string` | 失败原因代码，按它分支。取值见[失败原因](#失败原因)。 |
| `failed_reason.message` | `string` | 面向运营人员的说明，不要用于程序匹配。 |
| `created_timestamp` | `integer` | 该次转出的创建时间，Unix 时间戳（秒）。 |
| `updated_timestamp` | `integer` | 该次转出最近一次状态更新时间，Unix 时间戳（秒）。 |

### 失败原因

`failed_reason.code` 是您分支的依据。部分完成时，请先读对象级 `failed_reason`，无论失败发生在哪个阶段它都有值；如果起因是某笔转出交易，`transactions` 中对应的条目还会给出更精确的原因。

| `code` | 发生了什么 | 怎么处理 |
| --- | --- | --- |
| `payment.payout_partially_failed` | 这笔转出有一部分未能完成。`failed_amounts` 为未转出的金额。 | 这部分金额另建一笔转出。 |
| `transaction.rejected_by_policy` | 这笔转账命中了您自己配置的交易策略。 | 在 Cobo Portal 中调整该策略，然后重新创建转出。 |
| `transaction.rejected_by_approval` | 这笔转账在您组织的审批环节被拒绝——审批人拒绝，或您的回调服务器拒绝。 | 向对方确认原因，然后重新创建转出。 |
| `transaction.rejected_by_signer` | 这笔转账在签名环节被拒绝——co-signer 拒绝签名。 | 向 co-signer 确认原因，然后重新创建转出。 |
| `transaction.rejected_by_screening_app` | 您的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔转账。 | 到该应用查看原因，然后重新创建转出。 |
| `payment.payout_fee_charge_failed` | Fee Station 余额不足。 | 充值后重新创建转出。 |
| `payment.payout_fee_station_not_configured` | 未配置 Fee Station。 | 配置后重新创建转出。 |
| `payment.payout_fee_charge_failed_unknown` | 手续费因其他原因扣收失败。 | 检查 Fee Station 的配置与余额，然后重新创建转出。 |
| `payment.payout_sweep_failed` | 准备资金的归集交易失败。 | 重新创建转出。 |
| `payment.payout_bridge_failed` | 全部跨链交易失败，资产无法兑换。 | 确认该币种对存在可用的跨链路径，然后重新创建转出。 |
| `payment.payout_transactions_failed` | 全部转出交易均失败。逐笔原因在 `transactions` 中。 | 先看那里的明细再重试。 |
| `payment.payout_rejected_by_bank` | 收款银行退回了这笔转账，仅 Off-Ramp 会出现。**这不是终态。** | 与收款方核对账户信息，继续等后续事件。不要另建转出重发。 |
| `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔转账。 | 不要重试，联系 Cobo。 |
| `transaction.failed` | 原因无法归类。 | 不要重试，联系 Cobo 并提供 `payout_id`。 |

#### 重发失败的转出

原对象上没有重试。请创建一笔新的转出，并在自己的记录里保留原 `payout_id`，让两者可以关联——事件本身不携带指回原对象的引用。

## `payment.bank_withdrawal.status.updated`

银行提现状态变更时触发。银行提现把法币从您的某个虚拟账户转出到目标银行账户，通过 [Create bank withdrawal](/payments/en/api-references/payment/create-bank-withdrawal) 创建。

| `status` | 含义 |
| --- | --- |
| `Pending` | 银行提现已创建，等待处理。 |
| `Processing` | 银行提现处理中。 |
| `Completed` | 资金已离开虚拟账户。 |
| `Failed` | 银行提现失败，原因见 `failed_reason`。 |

**事件内容：** `data` 对象的 `data_type` 为 `PaymentBankWithdrawal`，并包含：

- `bank_withdrawal_id`（必填）—— Cobo 生成的银行提现 ID。
- `request_id`（必填）—— 您创建银行提现时提供的请求 ID。
- `source_bank_account_id`（必填）—— 来源银行账户 ID，必须是虚拟账户（标记为 `VA`）。
- `target_bank_account_id`（必填）—— 接收本次提现的目标银行账户 ID。
- `source_bank_account`（必填）—— 来源银行账户的完整信息。
- `target_bank_account`（必填）—— 目标银行账户的完整信息。
- `currency`（必填）—— 银行提现的法币币种，例如 `USD`。
- `amount`（必填）—— 银行提现金额，以该币种展示单位的十进制字符串表示，例如 `100.00`。
- `bank_tx_fee`（选填）—— 本次银行提现收取的银行交易手续费。
- `status`（必填）—— 当前状态，取值为 `Pending`、`Processing`、`Completed`、`Failed` 之一。
- `remark`（选填）—— 银行提现备注。
- `failed_reason`（选填）—— 银行提现失败的原因，仅当 `status` 为 `Failed` 时有值。
- `timeline`（必填）—— 银行提现的状态时间线。每一项包含一个 `status` 和进入该状态的 `timestamp`，Unix 时间戳（秒）。
- `created_timestamp`（必填）—— 创建时间，Unix 时间戳（秒）。

<Note>
  银行提现的 payload 不携带 `updated_timestamp`。要确定它何时进入当前状态，请读取 `timeline` 的最后一项。
</Note>

完整说明请参见 [Get bank withdrawal information](/payments/en/api-references/payment/get-bank-withdrawal-by-id)。
