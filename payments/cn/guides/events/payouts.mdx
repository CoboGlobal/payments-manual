本页的事件跟踪单笔资金转出或转账请求，无论是以加密货币结算，还是通过 Off-Ramp 结算到银行账户。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

批量转出请参见[批量下发事件](/payments/cn/guides/events/bulk-send)。

## 本页的事件

| 事件 | 通知什么 |
| --- | --- |
| `payment.payout.updated` | 一笔资金转出的结果：处理中、已完成、部分完成、失败，或被收款银行拒绝。 |
| `payment.bank_withdrawal.status.updated` | 从您的某个虚拟账户提现法币到银行账户的状态变更。 |

## `payment.payout.updated`

资金转出的主事件，以 `payout_id` 标识。

| `status` | 是否终态 | 您该做什么 |
| --- | --- | --- |
| `Pending` | 否 | 请求已受理，等待。 |
| `Preparing` | 否 | 等待。 |
| `Transferring` | 否 | 等待。**未到终态不能关闭本次转出**，即使部分转出交易已经完成。 |
| `Completed` | 是 | 关闭本次转出。这表示 Cobo 已完成转账，不表示收款方平台已经入账。 |
| `PartiallyCompleted` | 是 | 按 `failed_amounts` 的金额**另建一笔新的 Payout** 补发，不要重复支付已成功的部分。 |
| `Failed` | 是 | 读取 `failed_reason` 并处理，不要原地重试。 |
| `RejectedByBank` | 是 | 收款银行拒绝了这笔 Off-Ramp 转账。先与收款方核对账户信息，原样重发大概率会再次被拒。 |

### 事件内容

始终提供：`payout_id`、`request_id`、`source_account`、`status`、`requested_amounts`、`failed_amounts`、`requested_target`、`transactions`、`actual_payout_amount`、`initiator`、`commission_fees`、`remark`、`created_timestamp`、`updated_timestamp`。

| 字段 | 说明 |
| --- | --- |
| `payout_id` | 本次转出的身份，关闭转出和提交问题时使用的键。 |
| `request_id` | 您创建本次转出时提供的请求 ID。 |
| `source_account` | 转出资金来自哪个账户。 |
| `requested_target` | 业务意义上的收款目标。包含 `target_type`，取 `Address`（带 `address` 与 `chain_id`）或 `BankAccount`（带 `bank_account_id`、`account_alias`、`bank_name`、`currency`）。它不会暴露合约地址等链上执行细节。 |
| `initiator` | 转出发起人。 |
| `remark` | 转出备注。 |
| `transactions` | 转出交易列表，参见[读取交易数组](#读取交易数组)。 |
| `failed_reason` | 当 `status` 为 `Failed`、`RejectedByBank` 或 `PartiallyCompleted` 时出现。 |

### 金额分属两侧口径

| 字段 | 属于哪一侧 | 说明 |
| --- | --- | --- |
| `requested_amounts` | 源侧 | 您请求付出的金额，按源币种分组。 |
| `failed_amounts` | 源侧 | 其中没有付出去的部分，按源币种分组。到终态时，成功的金额等于两者之差。 |
| `actual_payout_amount` | 交付侧 | 收款方实际收到的金额。加密货币结算时为目标币种，Off-Ramp 时为银行账户的币种。转出完成前没有该值。 |
| `commission_fees` | 源侧 | Cobo 收取的佣金，每个 token 一条。收取与冲回相抵时某条可能为 `0` 或负数。 |

**不要跨两侧相减。** 跨链兑换和法币结算都会让两边不是同一种资产。

**不要用 `transactions` 去核对 `failed_amounts`。** 转出项可能在任何转出交易创建之前就失败——资金归集、跨链兑换、佣金扣收阶段——此时数组里根本没有对应条目。

### 读取交易数组

条目用 `result` 而不是 `status`，以避免与钱包交易状态混淆，取值为 `Completed`、`Failed` 和 `null`，其中 `null` 表示尚无结果。

每个条目包含 `transaction_id`、`amount`、`tx_hash` 和 `result`。交易广播前 `tx_hash` 为空。`result` 为 `Failed` 的条目带自己的 `failed_reason`，见[失败 code](#失败-code)。

经过跨链兑换后，条目的 `amount` 是实际转出时的币种，可能与 `requested_amounts` 中的源币种不同。

### 失败 code

`failed_reason.code` 是您分支的依据。部分完成时，请先读对象级 `failed_reason`，无论失败发生在哪个阶段它都有值；如果起因是某笔转出交易，`transactions` 中对应的条目还会给出更精确的原因。

| 怎么处理 | `code` | 发生了什么 |
| --- | --- | --- |
| 剩下的另建一笔转出 | `payment.payout_partially_failed` | 这笔转出有一部分未能完成。`failed_amounts` 就是需要重新转出的金额。 |
| 在您这边处理掉，然后重新创建转出 | `transaction.rejected_by_policy` | 这笔转账命中了您自己配置的交易策略。请在 Cobo Portal 中调整该策略。 |
| 在您这边处理掉，然后重新创建转出 | `transaction.rejected_by_approval` | 您组织内的审批人拒绝了这笔转账。请联系该审批人。 |
| 在您这边处理掉，然后重新创建转出 | `transaction.rejected_by_screening_app` | 您的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔转账。 |
| 处理 Fee Station，然后重新创建转出 | `payment.payout_fee_charge_failed` | Fee Station 余额不足。请充值。 |
| 处理 Fee Station，然后重新创建转出 | `payment.payout_fee_station_not_configured` | 未配置 Fee Station。请先配置。 |
| 处理 Fee Station，然后重新创建转出 | `payment.payout_fee_charge_failed_unknown` | 因其他原因扣收失败。请同时检查配置与余额。 |
| 直接重新创建转出 | `payment.payout_sweep_failed` | 准备资金的归集交易失败。 |
| 确认跨链路径后重新创建转出 | `payment.payout_bridge_failed` | 全部跨链交易失败，资产无法兑换。 |
| 先看交易明细 | `payment.payout_transactions_failed` | 全部转出交易均失败。逐笔原因在 `transactions` 中。 |
| 先与收款方核对账户信息 | `transaction.rejected_by_bank` | 收款银行退回了这笔转账，仅 Off-Ramp 会出现。原样重发大概率会再次被拒。 |
| 不要重试，联系 Cobo | `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔转账。 |
| 不要重试，联系 Cobo 并提供 `payout_id` | `transaction.failed` | 原因无法归类。 |

### 示例

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

#### 转出请求已受理

记录本次转出，不要重复提交。`requested_target` 是您自己的指令回显——请与您发出的内容核对。

```json
{
  "data_type": "PaymentPayoutUpdate",
  "payout_id": "payout_001",
  "request_id": "request_payout_001",
  "source_account": "developer",
  "status": "Pending",
  "requested_amounts": [
    { "amount": "500.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "failed_amounts": [],
  "requested_target": {
    "target_type": "Address",
    "address": "0xrecipient001",
    "chain_id": "ETH"
  },
  "transactions": [],
  "actual_payout_amount": null,
  "initiator": "api_key_abc123",
  "commission_fees": [],
  "remark": "September vendor settlement",
  "created_timestamp": 1744700000,
  "updated_timestamp": 1744700000
}
```

#### Off-Ramp 转出被银行拒绝

重发前先与收款方核对账户信息。`requested_target` 是银行账户，`actual_payout_amount` 本应为该账户的币种。

```json
{
  "data_type": "PaymentPayoutUpdate",
  "payout_id": "payout_004",
  "request_id": "request_payout_004",
  "source_account": "developer",
  "status": "RejectedByBank",
  "requested_amounts": [
    { "amount": "500.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "failed_amounts": [
    { "amount": "500.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "requested_target": {
    "target_type": "BankAccount",
    "bank_account_id": "ba_20260901_0007",
    "account_alias": "Vendor A operating account",
    "bank_name": "Example Bank",
    "currency": "USD"
  },
  "transactions": [],
  "actual_payout_amount": null,
  "initiator": "api_key_abc123",
  "commission_fees": [],
  "remark": null,
  "failed_reason": {
    "code": "transaction.rejected_by_bank",
    "message": "The receiving bank rejected this payout. Check the recipient's bank account details with them before resending — resending unchanged will most likely be rejected again."
  },
  "created_timestamp": 1744703000,
  "updated_timestamp": 1744703800
}
```

#### 重发失败的转出

原对象上没有重试。请创建一笔新的转出，并在自己的记录里保留原 `payout_id`，让两者可以关联——事件本身不携带指回原对象的引用。

## `payment.bank_withdrawal.status.updated`

银行提现状态变更时触发。银行提现把法币从您的某个虚拟账户转出到目标银行账户，通过 [Create bank withdrawal](/payments/en/api-references/payment/create-bank-withdrawal) 创建。

| `status` | 含义 |
| --- | --- |
| `Pending` | 银行提现已创建，等待处理。 |
| `Processing` | 银行提现处理中。 |
| `Completed` | 资金已离开虚拟账户。 |
| `Failed` | 银行提现失败，原因见 `failed_reason`。 |

**事件内容：** `data` 对象的 `data_type` 为 `PaymentBankWithdrawal`，并包含：

- `bank_withdrawal_id`（必填）—— Cobo 生成的银行提现 ID。
- `request_id`（必填）—— 您创建银行提现时提供的请求 ID。
- `source_bank_account_id`（必填）—— 来源银行账户 ID，必须是虚拟账户（标记为 `VA`）。
- `target_bank_account_id`（必填）—— 接收本次提现的目标银行账户 ID。
- `source_bank_account`（必填）—— 来源银行账户的完整信息。
- `target_bank_account`（必填）—— 目标银行账户的完整信息。
- `currency`（必填）—— 银行提现的法币币种，例如 `USD`。
- `amount`（必填）—— 银行提现金额，以该币种展示单位的十进制字符串表示，例如 `100.00`。
- `bank_tx_fee`（选填）—— 本次银行提现收取的银行交易手续费。
- `status`（必填）—— 当前状态，取值为 `Pending`、`Processing`、`Completed`、`Failed` 之一。
- `remark`（选填）—— 银行提现备注。
- `failed_reason`（选填）—— 银行提现失败的原因，仅当 `status` 为 `Failed` 时有值。
- `timeline`（必填）—— 银行提现的状态时间线。每一项包含一个 `status` 和进入该状态的 `timestamp`，Unix 时间戳（秒）。
- `created_timestamp`（必填）—— 创建时间，Unix 时间戳（秒）。

<Note>
  银行提现的 payload 不携带 `updated_timestamp`。要确定它何时进入当前状态，请读取 `timeline` 的最后一项。
</Note>

完整说明请参见 [Get bank withdrawal information](/payments/en/api-references/payment/get-bank-withdrawal-by-id)。
