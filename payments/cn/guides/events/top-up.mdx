本页覆盖充值模式：每个付款方有自己的入金地址，每笔入金单独跟踪。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

## 本页的事件

| 事件 | 通知什么 | 什么时候需要订阅 |
| --- | --- | --- |
| [`payment.topup.updated`](#payment-topup-updated) | 一笔充值的全过程：检测到、筛查中、可以入账、或者失败。 | 必选——这是充值业务的事件。 |
| [`payment.address.updated`](#payment-address-updated) | 某个付款方的入金地址被替换了。 | 必选。除了您自己发起的更换，**Cobo 也会主动更换地址**，那种情况下没有别的途径能知道。 |

## `payment.topup.updated`

充值模式的主事件。一笔入金对应一个对象，以 `transaction_id` 标识。

**只有 `status` 为 `Completed` 时才能入账**，没有第二个条件。

### 事件触发条件

**这笔充值的 `status` 每变化一次发一条事件。** `Completed` 与 `Failed` 是终态。

| 什么时候会收到 | `status` | 可否入账 | 您该做什么 |
| --- | --- | --- | --- |
| 入金地址上检测到这笔资金 | `Detected` | ❌ | 记录这笔待处理入金。 |
| 该笔入金进入合规筛查 | `PendingScreening` | ❌ | 等待。 |
| 筛查需要您处理（补交材料，或完成人工合规复核） | `ActionRequired` | ❌ | 按 `message` 处理。 |
| 筛查通过，且链上至少有一个确认 | `Completed` | ✅ | 按 `amount` 入账，以 `transaction_id` 作为幂等键。 |
| 该笔入金被拒绝或失败 | `Failed` | ❌ | 读取 `failed_reason.code` 决定下一步。 |

**金额不超过粉尘阈值的入金不发事件**，各 token 的阈值见登记入金地址接口返回的 `min_amount`（未单独配置的默认为 `0.05`，金额需严格大于该值）。

<Warning>
  **中间状态可能不出现。** 一笔入金可能从 `Detected` 直接跳到 `Completed`，中间的 `PendingScreening` 没有对应事件——这不代表它没经过筛查。请用每条事件里的 `status` 覆盖本地状态，不要校验状态迁移是否合法，也不要等 `PendingScreening` 再做什么。需要您动手的 `ActionRequired` 会一直停在那里，不会被跳过。
</Warning>

### 事件内容

<div className="field-table">

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `data_type` | `string` | 必填 | 固定为 `PaymentTopUpUpdate`。 |
| `transaction_id` | `string` | 必填 | 这笔入金的 ID。入账幂等用它，调用 Cobo 合规接口时也传它。 |
| `merchant_id` | `string` | 必填 | 这笔入金记在哪个商户名下。 |
| `payer_id` | `string` | 必填 | Cobo 分配的付款方 ID。 |
| `custom_payer_id` | `string` | 必填 | 您登记入金地址时提供的付款方 ID，未提供时为 `null`。 |
| `status` | `string` | 必填 | 当前状态，取值见[事件触发条件](#事件触发条件)。 |
| `amount` | `object` | 必填 | 这笔入金的金额、币种和链。全程不变，失败时也保留。 |
| `tx_hash` | `string` | 必填 | 链上交易哈希。Cobo 内部划转不上链，此时为 `null`，且不会后补。不要用它做幂等键。 |
| `topup_address` | `string` | 必填 | 收到这笔资金的入金地址，可据此确定对应的付款方和链。 |
| `source_address` | `string` | 必填 | 链上发送方，原路退回时作为转出目标。链上无法识别时为 `null`。 |
| `screening_mode` | `string` | 必填 | 这笔入金由哪套筛查体系处理，取 `CoboKyt`（Cobo 的 KYT）或 `IntegratedVendor`（Cobo 集成的第三方供应商），用于对账和排查。<br/>• 两种模式都可能需要您动手，**判断是不是轮到您处理请看 `status`**。<br/>• 筛查进行中也可能为 `null`，表示 Cobo 这次没查到供应商，不表示没有配置供应商。 |
| `message` | `string` | 必填 | `status` 为 `ActionRequired` 时说明该做什么，其余情况为 `null`。面向运营人员，**不要用于程序匹配**。两段固定文案：<br/>• `Additional information is required…`：查收 Cobo 发给您账户联系人的邮件，按邮件要求补充材料。<br/>• `A manual compliance review by your team is required…`：在 Screening App 中完成人工合规复核。 |
| `failed_reason` | `object` | 必填 | `status` 为 `Failed` 时给出 `{ code, message }`，其余情况为 `null`。取值见[失败原因](#失败原因)。 |
| `created_timestamp` | `integer` | 必填 | 这笔充值的创建时间，Unix 时间戳（秒）。 |
| `updated_timestamp` | `integer` | 必填 | 这笔充值最近一次状态更新时间，Unix 时间戳（秒）。 |

</div>

提交筛查结论时，调用 [Submit KYT screening decision](https://www.cobo.com/developers/v2/api-references/compliance/submit-kyt-screening-decision) 并传入本事件中的 `transaction_id`。资金退回、隔离、解冻同样按 `transaction_id` 定位，这些接口都不接受 `tx_hash`。

### 失败原因

`failed_reason.code` 是您分支的依据。入金只可能携带下面三个。提交问题时要提供的 ID 是 `transaction_id`。

| `code` | 发生了什么 | 怎么处理 |
| --- | --- | --- |
| `transaction.rejected_by_screening_app` | 您自己的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔入金。 | 到该应用查看原因。 |
| `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔入金。 | 与 Cobo 确认。 |
| `transaction.failed` | 其余全部情况，包括链上失败，以及因链重组而被回滚的入金。 | 提交问题并提供 `transaction_id`。 |

### 示例事件

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

#### 检测到一笔入金

把这笔入金标记为处理中，先不要入账。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "Detected",
  "amount": { "amount": "100", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "screening_mode": null,
  "message": null,
  "failed_reason": null,
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689000
}
```

#### 合规筛查进行中

继续等待。`screening_mode` 说明由哪套体系在审，但不代表需要您做什么。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "PendingScreening",
  "amount": { "amount": "100", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "screening_mode": "IntegratedVendor",
  "message": null,
  "failed_reason": null,
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689060
}
```

#### 筛查需要您处理

把这笔入金放进人工队列，按 `message` 决定做哪件事。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "ActionRequired",
  "amount": { "amount": "100", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "screening_mode": "CoboKyt",
  "message": "Additional information is required before these funds can be made available. Please check the email sent to your account contact.",
  "failed_reason": null,
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689100
}
```

#### 入金失败

停止任何自动入账，读取 `failed_reason.code`。本例是 Cobo 的合规检查拒绝，因此不要重发，先与 Cobo 解决。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "Failed",
  "amount": { "amount": "100", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "screening_mode": null,
  "message": null,
  "failed_reason": {
    "code": "transaction.rejected_by_compliance",
    "message": "This transaction was rejected by Cobo's compliance checks. Please do not resubmit it; contact Cobo support to resolve the issue first."
  },
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689400
}
```

## `payment.address.updated`

付款方的入金地址被替换时触发。请更新展示给该付款方的地址，并在旧地址仍可能收款期间继续接受其入金。

### 地址事件内容

<div className="field-table">

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `data_type` | `string` | 必填 | 固定为 `PaymentAddressUpdate`。 |
| `merchant_id` | `string` | 必填 | 该付款方属于哪个商户。 |
| `payer_id` | `string` | 必填 | 地址发生变更的付款方，Cobo 分配的 ID。 |
| `custom_payer_id` | `string` | 必填 | 同一付款方在您系统里的 ID，未提供时为 `null`。 |
| `chain` | `string` | 必填 | 该地址所属的链。只有这条链上的地址发生变更。 |
| `previous_address` | `string` | 必填 | 替换前的地址。 |
| `updated_address` | `string` | 必填 | 从现在起应展示给付款方的地址。 |

</div>

```json
{
  "data_type": "PaymentAddressUpdate",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "chain": "ETH",
  "previous_address": "0xtopup_addr_M1001_user_abc",
  "updated_address": "0xtopup_addr_M1001_user_abc_new"
}
```
