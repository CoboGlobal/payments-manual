本页覆盖充值模式：每个付款方有自己的入金地址，每笔入金单独跟踪。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

## 本页的事件

| 事件 | 通知什么 | 什么时候需要订阅 |
| --- | --- | --- |
| [`payment.topup.updated`](#paymenttopupupdated) | 一笔充值的全过程：检测到、筛查中、可以入账、或者失败。 | 必选——这是充值业务的事件。 |
| [`payment.address.updated`](#paymentaddressupdated) | 某个付款方的入金地址被替换了。 | 必选。除了您自己发起的更换，**Cobo 也会主动更换地址**，那种情况下没有别的途径能知道。 |
| [`payment.transaction.external.created`](#paymenttransactionexternal) | 收到一笔不属于任何入金计划、或使用了不支持币种的入金。 | 必选。这类入金不属于任何付款方或订单，没有别的事件会告诉您它到了。 |
| [`payment.transaction.external.completed`](#paymenttransactionexternal) | 那笔意外入金通过了筛查，已计入您的开发者余额。 | 必选。同上，这一条告诉您它已经入账。 |

## `payment.topup.updated`

充值模式的主事件。一笔入金对应一个对象，以 `transaction_id` 标识。

**只有 `status` 为 `Completed` 时才能入账**，没有第二个条件。

| `status` | 是否终态 | 可否入账 | 您该做什么 |
| --- | --- | --- | --- |
| `Detected` | 否 | 否 | 记录这笔待处理入金。 |
| `PendingScreening` | 否 | 否 | 等待，合规筛查进行中。 |
| `ActionRequired` | 否 | 否 | 需要您处理。读取 `message` 判断需要做哪件事。 |
| `Completed` | 是 | 是 | 按 `amount` 入账，以 `transaction_id` 作为幂等键。 |
| `Failed` | 是 | 否 | 读取 `failed_reason.code` 决定下一步。 |

所有入金都会经过筛查，因此不存在从 `Detected` 直达 `Completed` 的路径。`ActionRequired` 在您处理之后回到 `PendingScreening`，是唯一会回退的状态。

### 事件内容

始终提供：`transaction_id`、`merchant_id`、`payer_id`、`custom_payer_id`、`status`、`amount`、`tx_hash`、`topup_address`、`source_address`、`created_timestamp`、`updated_timestamp`。

| 字段 | 说明 |
| --- | --- |
| `transaction_id` | 这笔入金的交易 ID，也是对象身份。调用 Cobo 合规相关接口时传的就是它。 |
| `payer_id` / `custom_payer_id` | Cobo 分配的付款方标识，以及您自己分配的标识。 |
| `amount` | 资产金额，包含 `amount`、`token_id`、`chain_id`。从首条事件起即有值，失败时也保留，因此它说明的是这笔入金有多少钱，不是这笔钱能不能用。 |
| `tx_hash` | 链上交易哈希。Cobo 内部划转不上链，此时没有该值。 |
| `topup_address` | 收到这笔资金的入金地址。 |
| `source_address` | 链上发送方。链上无法识别时为 `null`。 |
| `screening_mode` | 筛查进行中时提供，参见[筛查模式](#筛查模式)。 |
| `message` | 仅当 `status` 为 `ActionRequired` 时出现，面向运营人员。 |
| `failed_reason` | 仅当 `status` 为 `Failed` 时出现，包含 `code` 与 `message`，取值见[失败 code](#失败-code)。 |

### `status` 为 `ActionRequired` 时

三种情况共用这个状态，靠 `message` 区分。由于 `message` 不能用于程序匹配，这三类目前无法自动分流，需要进入人工队列。

| 您需要做什么 | `message` 会提示 |
| --- | --- |
| 查收 Cobo 发给您账户联系人的邮件，并按邮件要求补充材料。 | `Additional information is required…Please check the email…` |
| 在 Screening App 中提交您自有 KYT 供应商的扫描结论。 | `A screening result from your own KYT provider is required…` |
| 在 Screening App 中完成人工合规复核。 | `A manual compliance review by your team is required…` |

提交筛查结论时，调用 [Submit KYT screening decision](https://www.cobo.com/developers/v2/api-references/compliance/submit-kyt-screening-decision) 并传入本事件中的 `transaction_id`。资金退回、隔离、解冻同样按 `transaction_id` 定位，这些接口都不接受 `tx_hash`。

### 筛查模式

`screening_mode` 说明这笔入金由哪套筛查体系处理，取 `CoboKyt`、`IntegratedVendor` 或 `CustomVendor`，用于对账和排查。

三种模式下都可能需要您动手，因此它不能用来判断是不是轮到您处理——这件事由 `status` 表达。筛查进行中时该字段也可能没有值，那表示 Cobo 此次没有查到供应商，不表示没有配置供应商。

### 失败 code

`failed_reason.code` 是您分支的依据。入金只可能携带下面三个。提交问题时要提供的 ID 是 `transaction_id`。

| `code` | 发生了什么 | 怎么处理 |
| --- | --- | --- |
| `transaction.rejected_by_screening_app` | 您自己的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔入金。 | 到该应用查看原因。 |
| `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔入金。 | 与 Cobo 确认。 |
| `transaction.failed` | 其余全部情况，包括链上失败，以及因链重组而被回滚的入金。 | 提交问题并提供下面这个 ID。 |

### 充值示例

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

#### 检测到一笔入金

把这笔入金标记为处理中，先不要入账。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "Detected",
  "amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689000
}
```

#### 合规筛查进行中

继续等待。`screening_mode` 说明由哪套体系在审，但不代表需要您做什么。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "PendingScreening",
  "screening_mode": "IntegratedVendor",
  "amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689060
}
```

#### 筛查需要您处理

把这笔入金放进人工队列。三种可能的动作靠 `message` 区分，参见 [`status` 为 `ActionRequired` 时](#status-为-actionrequired-时)。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "ActionRequired",
  "screening_mode": "CoboKyt",
  "amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "message": "Additional information is required before these funds can be made available. Please check the email sent to your account contact.",
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689100
}
```

#### 资金可用

**只有这个状态可以入账。** 以 `transaction_id` 作为幂等键。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "Completed",
  "amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689300
}
```

#### 入金失败

停止任何自动入账，读取 `failed_reason.code`。本例是 Cobo 的合规检查拒绝，因此不要重发，先与 Cobo 解决。

```json
{
  "data_type": "PaymentTopUpUpdate",
  "transaction_id": "aff0e1cb-15b2-4e1f-9b9d-a9133715986f",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "status": "Failed",
  "amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xabc123",
  "topup_address": "0xtopup_addr_M1001_user_abc",
  "source_address": "0xsender001",
  "failed_reason": {
    "code": "transaction.rejected_by_compliance",
    "message": "Cobo's compliance checks rejected this transaction. Do not resend it — contact Cobo support to resolve the issue first."
  },
  "created_timestamp": 1744689000,
  "updated_timestamp": 1744689400
}
```

## `payment.address.updated`

付款方的入金地址被替换时触发。请更新展示给该付款方的地址，并在旧地址仍可能收款期间继续接受其入金。

**事件内容：**

| 字段 | 说明 |
| --- | --- |
| `payer_id` / `custom_payer_id` | 地址发生变更的付款方。 |
| `chain` | 该地址所属的链。只有这条链上的地址发生变更。 |
| `previous_address` | 替换前的地址。 |
| `updated_address` | 从现在起应使用的地址。 |

### 地址替换示例

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

#### 付款方的地址被替换

更新展示给该付款方的地址。这是 `payment.address.updated` 事件，不是充值事件。

```json
{
  "data_type": "PaymentAddressUpdate",
  "merchant_id": "M1001",
  "payer_id": "P20250619T0310056d7aa",
  "custom_payer_id": "user_abc_10001",
  "chain": "ETH",
  "previous_address": "0xtopup_addr_M1001_user_abc",
  "updated_address": "0xtopup_addr_M1001_user_abc_new"
}
```

## `payment.transaction.external.*`

不属于任何入金计划、或使用了不支持币种的入金，不会作为充值处理，而是作为意外入金上报，并计入您的开发者余额而不是某个付款方。

两者携带的字段见[高级事件](/payments/cn/guides/events/advanced#交易字段)。订单模式下同样会出现意外入金，参见[订单事件](/payments/cn/guides/events/orders#paymenttransactionexternal)。

## 相关

- 需要确认数、手续费明细，以及每笔入金背后的链上细节时，订阅 `payment.transaction.created`、`payment.transaction.completed` 和 `payment.transaction.failed`。参见[高级事件](/payments/cn/guides/events/advanced)。
- `payment.account.balance.updated` 汇报相应的余额变动。参见[余额变动](/payments/cn/guides/events/balances)。
