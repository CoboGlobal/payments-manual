交易级事件汇报的是底层交易本身，而不是这个业务对象接下来需要什么，属于高级选项：业务对象事件已经告诉您能否入账、能否发货、能否关闭转出，而交易级事件位于它下面一层，暴露背后的细节。

这一类别包含两族事件：

| 族 | 事件 |
| --- | --- |
| `payment.transaction.*` | 单笔链上交易，列在本页。 |
| `*.status.updated` | `payment.order.status.updated`、`payment.refund.status.updated`、`payment.payout.status.updated`、`payment.bulk_send.status.updated`、`payment.bulk_send.item.status.updated`。它们各自返回所属对象的交易信息——`transactions` 数组、费用字段、校验状态——说明在对应的业务页面上。 |

当您需要确认数、手续费明细、区块信息，或替换（丢弃、重发、加速）信息时订阅它们——例如向付款方展示转账进度，或核对 gas 支出。判断下一步该做什么，请使用业务对象事件。

请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

`*.status.updated` 这一族请到对应的业务页面查看：[订单](/payments/cn/guides/events/orders)、[退款](/payments/cn/guides/events/refunds)、[资金转出](/payments/cn/guides/events/payouts)、[批量下发](/payments/cn/guides/events/bulk-send)。本页其余部分覆盖 `payment.transaction.*` 这一族，以及它们共用的交易字段。

<Note>
  不要同时用业务对象事件和交易级事件驱动同一个不可逆动作。入账、发货、关闭付款三件事各自选定一个来源，另一个仅用于对账。
</Note>

## 入金交易

| 事件 | 触发时机 | 适用范围 |
| --- | --- | --- |
| `payment.transaction.created` | 入金地址收到一笔新的入金。 | 充值模式 |
| `payment.transaction.completed` | 一笔入金通过合规筛查并已入账。 | 两种收款模式 |
| `payment.transaction.failed` | 一笔入金未通过合规筛查。 | 两种收款模式 |
| `payment.transaction.late` | 订单进入终态后，又收到一笔通过筛查的入金。 | 订单模式 |

它们在共用[交易字段](#交易字段)之外，各自附加以下字段：

| 事件 | 附加字段 |
| --- | --- |
| `payment.transaction.created` | `acquiring_type`（必填，值为 `TopUp`）、`payer_id`（选填）、`custom_payer_id`（选填） |
| `payment.transaction.completed` | 订单模式：`acquiring_type`（必填，值为 `Order`）、`order_id`（选填）、`psp_order_code`（选填）。充值模式：`acquiring_type`（必填，值为 `TopUp`）、`payer_id`（选填）、`custom_payer_id`（选填） |
| `payment.transaction.failed` | `acquiring_type`（必填，`Order` 或 `TopUp`）、`order_id`（选填）、`psp_order_code`（选填）、`payer_id`（选填）、`custom_payer_id`（选填） |
| `payment.transaction.late` | `acquiring_type`（必填，值为 `Order`）、`order_id`（选填）、`psp_order_code`（选填） |

对于分多笔付清的订单，`payment.transaction.completed` 在每笔资金入账时各触发一次，而订单事件汇报的是累计结果。参见[少付、多付、部分付款和晚付](/payments/cn/guides/create-orders#少付多付部分付款和晚付)。

`payment.transaction.late` 不会重开订单，也不会改变订单的终态。同一个事实也会通过订单事件的 `notice_type` 为 `LatePaymentReceived` 送达。参见[少付、多付、部分付款和晚付](/payments/cn/guides/create-orders#少付多付部分付款和晚付)。

## 对象的交易级事件

这些事件返回的是对象底层的交易信息——`transactions` 数组、费用字段、校验状态——而不是这个对象接下来需要什么。每一个都与覆盖同一链路的业务对象事件同时投递，对应关系见下表。

| 事件 | 覆盖同一链路的业务对象事件 |
| --- | --- |
| `payment.order.status.updated` | [`payment.order.updated`](/payments/cn/guides/events/orders) |
| `payment.refund.status.updated` | [`payment.refund.updated`](/payments/cn/guides/events/refunds) |
| `payment.payout.status.updated` | [`payment.payout.updated`](/payments/cn/guides/events/payouts) |
| `payment.bulk_send.status.updated` | [`payment.bulk_send.updated`](/payments/cn/guides/events/bulk-send) |
| `payment.bulk_send.item.status.updated` | [`payment.bulk_send.item.updated`](/payments/cn/guides/events/bulk-send) |

**判断请用业务对象事件，这些事件用于对账。** 不要用两边各触发一次入账、发货或关闭转出。

### `payment.order.status.updated`

**触发条件：** 支付订单状态发生变更时触发（仅限订单模式）。会触发的节点包括：
- `Pending`：此状态通知仅限于通过支付链接成功创建订单时触发。
- `Completed`：在订单有效期内收到全额付款。
- `Expired`：订单有效期内没有已完成的充币交易，或者订单已被取消。
- `Underpaid`：订单有效期内存在已完成的充币交易，但实收金额少于应付金额。

**事件内容：**
- `order_id`（必填）— 订单 ID。
- `merchant_id`（选填）— 商户 ID。
- `merchant_order_code`（选填）— 商户分配的唯一参考编码。
- `psp_order_code`（必填）— 开发者用于标识该订单的唯一参考编码。
- `pricing_currency`（选填）— 订单的计价货币。
- `pricing_amount`（选填）— 订单的基础金额（不含开发者手续费）。
- `fee_amount`（必填）— 该订单的开发者手续费。
- `payable_currency`（选填）— 用于付款的加密货币 ID。
- `chain_id`（必填）— 区块链网络 ID。
- `payable_amount`（必填）— 该订单需支付的加密货币金额。
- `exchange_rate`（必填）— `payable_currency` 与 `pricing_currency` 之间的汇率。
- `amount_tolerance`（选填）— 允许的金额偏差。
- `receive_address`（必填）— 收款钱包地址。
- `status`（必填）— 当前订单状态，可能的值：`Pending`、`Processing`、`Completed`、`Expired`、`Underpaid`。
- `received_token_amount`（必填）— 该订单已收到的加密货币总金额。
- `expired_at`（选填）— 过期时间，Unix 时间戳（秒）。
- `created_timestamp`（选填）— 创建时间，Unix 时间戳（秒）。
- `updated_timestamp`（选填）— 最后更新时间，Unix 时间戳（秒）。
- `transactions`（选填）— 与该订单关联的支付交易数组。

完整字段说明请参考 [Get pay-in order information](/payments/en/api-references/payment/get-pay-in-order-information)。

### `payment.refund.status.updated`

返回的是该退款底层的交易信息，包括 `transactions` 数组和费用字段。

**触发条件：** 退款单状态变更。关键节点为 `Pending`（通过退款链接成功创建退款单）、`Completed`（全部退款交易完成）、`Failed`（全部退款交易失败）。

**事件内容：**

- `refund_id`（必填）—— 退款单 ID。
- `request_id`（选填）—— 您创建退款时提供的请求 ID。
- `order_id`（选填）—— 本次退款对应的收款订单 ID。
- `merchant_id`（选填）—— 商户 ID。
- `token_id`（必填）—— 退款使用的加密货币 ID。
- `chain_id`（必填）—— 区块链网络 ID。
- `amount`（必填）—— 本次退款需退还的加密货币金额。
- `to_address`（必填）—— 收款钱包地址。
- `status`（必填）—— 当前退款状态，取值为 `AddressPending`、`AddressSubmitted`、`Pending`、`Processing`、`Completed`、`Failed`、`PendingConfirmation` 之一。
- `refund_type`（选填）—— 资金来源，取值为 `Merchant` 或 `Psp`。
- `created_timestamp`（必填）—— 创建时间，Unix 时间戳（秒）。
- `updated_timestamp`（必填）—— 最近更新时间，Unix 时间戳（秒）。
- `initiator`（选填）—— 退款请求发起人。
- `transactions`（选填）—— 与该退款关联的支付交易数组。
- `charge_merchant_fee`（选填）—— 是否向商户收取开发者手续费。
- `merchant_fee_amount`（选填）—— 向商户收取的开发者手续费金额。
- `merchant_fee_token_id`（选填）—— 开发者手续费使用的加密货币 ID。
- `commission_fee`（选填）—— 佣金明细。

完整说明请参见 [Get refund order information](/payments/en/api-references/payment/get-refund-order-information)。

### `payment.payout.status.updated`

返回的是该次转出底层的交易信息，包括 `transactions` 数组和 `payout_items`。

**触发条件：** 资金转出或转账请求状态变更。`Completed` 表示全部转账完成，`PartiallyCompleted` 表示部分完成、部分失败，`Failed` 表示全部失败，`RejectedByBank` 表示收款银行拒绝了 Off-Ramp 转出。

**事件内容：**

- `payout_id`（必填）—— 资金转出 ID。
- `request_id`（必填）—— 您创建本次转出时提供的请求 ID。
- `payout_channel`（必填）—— 转出渠道，取值为 `Crypto` 或 `OffRamp`。
- `source_account`（选填）—— 转出来源账户。
- `payout_items`（选填）—— 转出项数组。
- `recipient_info`（选填）—— 收款方信息。
- `initiator`（选填）—— 转出请求发起人。
- `actual_payout_amount`（选填）—— 收款方实际收到的金额。
- `commission_fees`（选填）—— 本次转出的佣金数组。
- `remark`（选填）—— 转出备注。
- `status`（必填）—— 当前转出状态，取值为 `Pending`、`Preparing`、`Transferring`、`Completed`、`PartiallyCompleted`、`Failed`、`RejectedByBank` 之一。
- `created_timestamp`（必填）—— 创建时间，Unix 时间戳（秒）。
- `updated_timestamp`（必填）—— 最近更新时间，Unix 时间戳（秒）。
- `transactions`（选填）—— 与该次转出关联的支付交易数组。

完整说明请参见 [Get payout information](/payments/en/api-references/payment/get-payout-information)。

### `payment.bulk_send.status.updated`

**触发条件：** 批量下发请求状态变更。`Completed` 表示全部下发完成，`PartiallyCompleted` 表示部分完成、部分失败，`Failed` 表示全部失败。

**事件内容：**

- `bulk_send_id`（必填）—— 批量下发 ID。
- `request_id`（选填）—— 您创建批量下发时提供的请求 ID。
- `source_account`（必填）—— 批量下发的来源账户。
- `description`（选填）—— 整个批次的描述。
- `execution_mode`（必填）—— 执行模式。
- `status`（必填）—— 当前批量下发状态。
- `created_timestamp`（必填）—— 创建时间，Unix 时间戳（秒）。
- `updated_timestamp`（必填）—— 最近更新时间，Unix 时间戳（秒）。

完整说明请参见 [Get bulk send information](/payments/en/api-references/payment/get-bulk-send-information)。

### `payment.bulk_send.item.status.updated`

**触发条件：** 单个批量下发条目的状态变更。可用于跟踪条目级执行结果，尤其是批次部分完成、或个别条目校验失败或转账失败时。

**事件内容：**

- `bulk_send_item_id`（必填）—— 批量下发条目 ID。
- `bulk_send_id`（必填）—— 该条目所属的批量下发 ID。
- `request_id`（选填）—— 批次的请求 ID。
- `source_account`（必填）—— 批次的来源账户 ID。
- `token_id`（必填）—— 下发给收款方的加密货币 ID。
- `receiving_address`（必填）—— 收款方的加密货币地址。
- `amount`（必填）—— 下发给收款方的加密货币金额。
- `description`（选填）—— 该条目的备注。
- `tx_hash`（选填）—— 该条目的交易哈希。
- `status`（必填）—— 条目执行状态，取值为 `Pending`、`Processing`、`Completed`、`Failed`、`NotExecuted` 之一。
- `validation_status`（必填）—— 条目校验状态，取值为 `Pending`、`Validated`、`ValidationFailed`、`NotExecuted` 之一。
- `failed_reason`（选填）—— 该条目失败的原因。
- `created_timestamp`（必填）—— 创建时间，Unix 时间戳（秒）。
- `updated_timestamp`（必填）—— 最近更新时间，Unix 时间戳（秒）。

要测试投递到您已注册的 Webhook 接收端，请使用 [Trigger test webhook event](/payments/en/api-references/payment/trigger-test-webhook-event)，并将 `event_type` 设为 `payment.bulk_send.item.status.updated`。

## 交易字段

以下字段出现在所有 `payment.transaction.*` 事件中。并非每个字段在每种场景下都有值。

<Note>
  本节只覆盖与支付场景最相关的字段。完整的交易字段及其含义，请参见 [Get transaction information](https://www.cobo.com/developers/v2/api-references/transactions/get-transaction-information)。
</Note>

- `transaction_id`（string，UUID，必填）—— 交易 ID。
- `cobo_id`（string，选填）—— 用于追踪交易的 Cobo ID。
- `request_id`（string，选填）—— 用于追踪交易请求的请求 ID。
- `type`（string，选填）—— 交易类型。
- `status`（string，必填）—— 交易状态，例如 `Submitted`、`PendingScreening`、`Confirming`、`Completed`、`Failed`、`Rejected`。完整生命周期参见 [Transaction statuses and sub-statuses](https://www.cobo.com/developers/v2/guides/transactions/status)。其中 `PendingAuthorization` 既涵盖人工审批环节，也涵盖内部自动的风控、KYT、合规检查，不一定需要人工操作。
- `sub_status`（string，选填）—— 与 `status` 并列的更细粒度状态，例如 `PendingApproverCheck`、`RejectedKYT`、`FailedOnChain`。完整取值同样参见上述[状态与子状态文档](https://www.cobo.com/developers/v2/guides/transactions/status)。
- `failed_reason`（string，选填）—— 交易失败的原因，仅在审批失败和签名失败时有值。它是一个自由文本字符串，与业务对象事件携带的 `{ code, message }` 对象不同。
- `initiator`（string，选填）—— 交易发起人。
- `chain_id`（string，选填）—— 链 ID。
- `token_id`（string，选填）—— token ID。
- `transaction_hash`（string，选填）—— 链上交易哈希（`txid`）。只有交易在链上广播之后才有值，在此之前可能为 `null` 或不存在；而 `transaction_id` 在创建时即分配，始终存在。
- `source`（object，必填）—— 入金来源，通常是一个外部钱包地址（`source_type: DepositFromAddress`）。
- `destination`（object，必填）—— 入金去向，通常是一个入金地址（`destination_type: DepositToAddress`）。关键子字段：
  - `address` —— 收款地址。
  - `amount` —— 收到的金额。例如存入 1.5 USDT 时该值为 `1.5`。
  - `memo` —— 用于识别应入账到哪个账户的备注，仅部分链有。
- `result`（object，选填）—— 交易结果。
- `fee`（object，选填）—— 交易手续费。其结构取决于该链的手续费模型，例如 EIP-1559、UTXO。
- `confirmed_num`（integer，选填）—— 该交易已获得的确认数。
- `confirming_threshold`（integer，选填）—— 认定交易安全所需的最小确认数，例如比特币交易通常为 6。
- `block_info`（object，选填）—— 该交易所在区块的信息：
  - `block_number` —— 区块高度。
  - `block_timestamp` —— 区块创建时间，Unix 时间戳（毫秒）。
  - `block_hash` —— 区块哈希。
- `raw_tx_info`（object，选填）—— 原始交易信息：
  - `used_nonce` —— 交易 nonce。
  - `selected_utxos` —— 该交易消耗的 UTXO。
  - `raw_tx` —— 原始交易数据。
  - `unsigned_raw_tx` —— 未签名的原始交易数据。
  - `utxo_changes` —— 该交易中的 UTXO 找零输出。
- `replacement`（object，选填）—— 当该交易替换了另一笔交易、或被另一笔交易替换时有值（丢弃、重发、加速）：
  - `replaced_by_type` / `replaced_type` —— 替换类型，取 `Drop`、`Resend` 或 `SpeedUp`。
  - `replaced_by_transaction_id` / `replaced_by_transaction_hash` —— 替换了本交易的那笔交易的 ID 与哈希。
  - `replaced_transaction_id` / `replaced_transaction_hash` —— 被本交易替换的那笔交易的 ID 与哈希。
- `created_timestamp`（integer，int64，必填）—— 创建时间，Unix 时间戳（毫秒）。
- `updated_timestamp`（integer，int64，必填）—— 最近更新时间，Unix 时间戳（毫秒）。
