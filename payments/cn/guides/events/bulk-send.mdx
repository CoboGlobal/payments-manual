批量下发有两级事件：一级是批次，一级是批次里的每个条目。只需要批次结论就订阅批次事件，需要逐条对账就订阅条目事件。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

## 本页的事件

| 事件 | 通知什么 | 什么时候需要订阅 |
| --- | --- | --- |
| [`payment.bulk_send.updated`](#payment-bulk_send-updated) | 一个批次的结果，以及金额和数量汇总。 | 必选——这是批次的事件。 |
| [`payment.bulk_send.item.updated`](#payment-bulk_send-item-updated) | 单个条目的结果，用于与您自己的收款人记录对账。 | 需要逐条对账、而不只要批次结论时。 |

## `payment.bulk_send.updated`

批次级事件，以 `bulk_send_id` 标识。

### 批次的事件触发条件

**批次 `status` 每变化一次发一条事件。** 逐条进度不在这里，在条目事件里。

| 什么时候会收到 | `status` | 您该做什么 |
| --- | --- | --- |
| 批次创建成功 | `Pending` | 建立批次记录并等待。停在这里不一定是在校验，也可能在等审批，见下方说明。 |
| 批次进入逐项校验 | `Validating` | 等待。此时还不知道哪些条目会被拒。 |
| 校验通过，开始逐项执行 | `Transferring` | 等待。 |
| 全部条目成功 | `Completed` | 关闭批次汇总。条目的完成仍以条目事件为准。 |
| 批次结果确定，部分条目未成功 | `PartiallyCompleted` | 按两个计数分流：`failed_item_count` 为已提交执行但失败的条目，`not_executed_item_count` 为从未提交执行的条目。 |
| 批次整体失败 | `Failed` | 读取 `failed_reason.code`——**执行前后都可能失败**，资金是否已被使用以它为准，见[批次的失败原因](#批次的失败原因)。 |

启用了审批流的组织，批次创建后会先等审批。**审批过程不发事件，事件里也没有字段能区分「等校验」和「等审批」**，两者的 `status` 都是 `Pending`。批次在 `Pending` 停留时间较长时，请在 Cobo Portal 查看审批进度。审批的结果是可见的：通过后批次继续走到 `Validating`；被拒或被撤销时批次进入 `Failed`，条目的 `failed_reason.code` 为 `payment.app_workflow_approval_rejected` 或 `payment.app_workflow_approval_revoked`。

### 批次的事件内容

<div className="field-table">

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `data_type` | `string` | 必填 | 固定为 `PaymentBulkSendUpdate`。 |
| `bulk_send_id` | `string` | 必填 | 批次 ID。 |
| `request_id` | `string` | 选填 | 您创建批次时提供的请求 ID。 |
| `source_account` | `string` | 必填 | 批次的付款账户：商户账户为商户 ID，开发者账户为 `developer`。 |
| `status` | `string` | 必填 | 批次当前状态，含义见[批次的事件触发条件](#批次的事件触发条件)：<br/>• `Pending`<br/>• `Validating`<br/>• `Transferring`<br/>• `Completed`<br/>• `PartiallyCompleted`<br/>• `Failed` |
| `execution_mode` | `string` | 必填 | 执行模式：<br/>• `Strict`：只要有条目**校验**不通过，整批都不执行。<br/>• `Partial`：只隔离未通过校验的条目，其余继续执行。<br/>`Strict` 只作用于校验阶段，**不保证上链后全部成功或全部失败**——全部条目通过校验、提交转出后个别失败时，批次为 `PartiallyCompleted`。 |
| `item_count` | `integer` | 必填 | 批次包含的条目数。 |
| `failed_item_count` | `integer` | 必填 | 已提交执行但失败的条目数。这些条目的资金曾被锁定、手续费曾被扣收，现已释放和退回。能否直接重发取决于各条目的 `failed_reason.code`。 |
| `not_executed_item_count` | `integer` | 必填 | 从未提交执行的条目数，这些条目的资金未被使用。不修正原因就重发会以同样方式失败。 |
| `requested_amounts` | `array` | 必填 | 全部条目的请求金额合计，按 `token_id` 分组。同一币种在两条链上是两项，不能合并。 |
| `requested_amounts[].amount` | `string` | 必填 | 金额，十进制字符串。 |
| `requested_amounts[].token_id` | `string` | 必填 | 币种 ID。 |
| `requested_amounts[].chain_id` | `string` | 必填 | 链 ID。 |
| `completed_amounts` | `array` | 必填 | 已完成条目的金额合计，按 `token_id` 分组。 |
| `completed_amounts[].amount` | `string` | 必填 | 金额，十进制字符串。 |
| `completed_amounts[].token_id` | `string` | 必填 | 币种 ID。 |
| `completed_amounts[].chain_id` | `string` | 必填 | 链 ID。 |
| `failed_amounts` | `array` | 必填 | 未成功条目的金额合计，按 `token_id` 分组，已提交执行的与从未提交的合并计算。区分两者请看 `failed_item_count` 与 `not_executed_item_count`。 |
| `failed_amounts[].amount` | `string` | 必填 | 金额，十进制字符串。 |
| `failed_amounts[].token_id` | `string` | 必填 | 币种 ID。 |
| `failed_amounts[].chain_id` | `string` | 必填 | 链 ID。 |
| `description` | `string` | 必填 | 您创建批次时填写的整批备注，未填写时为 `null`。 |
| `commission_fee` | `object` | 必填 | Cobo 收取的佣金，未产生时为 `null`。 |
| `commission_fee.fee_amount` | `string` | 必填 | 佣金金额，**单位为美元**。佣金从 Fee Station 扣，余额按美元计，因此不带币种。批次跨多少种 token 都只给出一个总额。退费冲抵后可能为 `0` 或负数。 |
| `failed_reason` | `object` | 必填 | `status` 为 `Failed` 时有值，其余情况为 `null`。 |
| `failed_reason.code` | `string` | 必填 | 失败原因代码，按它分支。取值见[批次的失败原因](#批次的失败原因)。 |
| `failed_reason.message` | `string` | 必填 | 面向运营人员的说明，不要用于程序匹配。 |
| `created_timestamp` | `integer` | 必填 | 该批次的创建时间，Unix 时间戳（秒）。 |
| `updated_timestamp` | `integer` | 必填 | 该批次最近一次状态更新时间，Unix 时间戳（秒）。 |

</div>

`failed_amounts` 把两类未成功条目——已提交执行的和从未提交的——按 token 合并为一个金额。要区分它们，请使用 `failed_item_count` 与 `not_executed_item_count`，或查看条目事件。

批次事件**不携带条目列表**。逐条信息只通过条目事件送达，且两者的到达顺序不作保证。

### 批次的失败原因

`failed_reason.code` 是您分支的依据，也是判断资金是否已被使用的唯一依据——`status` 本身无法区分。批次也可能因为审批被拒绝或被撤销而失败，该原因汇报在条目上。

| `code` | 发生了什么 | 资金是否已被使用 | 怎么处理 |
| --- | --- | --- | --- |
| `payment.bulk_send_no_valid_items` | 没有任何条目通过校验。 | 没有 | 修正条目后创建新批次。 |
| `payment.bulk_send_strict_validation_failed` | `execution_mode` 为 `Strict` 且有条目未通过校验，批次因此中止。 | 没有 | 修正那些条目后创建新批次。 |
| `payment.bulk_send_commission_fee_all_failed` | 所有条目的佣金都未能扣收。 | 没有付款 | 处理 Fee Station 后创建新批次。 |
| `payment.bulk_send_strict_commission_fee_failed` | `execution_mode` 为 `Strict` 且有条目的佣金扣收失败。 | 没有付款 | 处理 Fee Station 后创建新批次。 |
| `payment.bulk_send_strict_sweep_failed` | `execution_mode` 为 `Strict` 且有归集交易失败。 | 已归集，未付款 | 创建新批次。 |
| `payment.bulk_send_all_items_failed` | 一个成功的条目都没有——可能全部提交后失败，也可能一笔都没提交。 | 看两个计数：`failed_item_count` 大于 `0` 表示有条目提交过并失败；`not_executed_item_count` 等于 `item_count` 表示一笔都没提交 | 逐条读条目事件的原因，修正后创建新批次。 |

## `payment.bulk_send.item.updated`

条目级事件，以 `bulk_send_item_id` 标识。

### 条目的事件触发条件

**条目 `status` 每变化一次发一条事件。**

| 什么时候会收到 | `status` | 您该做什么 |
| --- | --- | --- |
| 条目随批次创建，或校验通过但尚未提交转出 | `Pending` | 建立条目记录。**这个值覆盖两个阶段**，停留在此状态不代表仍在校验。 |
| 该条目的转出已提交 | `Processing` | 等待结果，不要标记完成。 |
| 转出成功 | `Completed` | 保存金额和 `tx_hash`，关闭该条目。 |
| 转出已提交但失败 | `Failed` | 锁定资金已释放、手续费已退回。能否原样重发取决于 `failed_reason.code`。 |
| 该条目从未提交执行 | `NotExecuted` | **资金未被使用。** 读取 `failed_reason.code`，不修正原因就重发会再次失败。 |

### 条目的事件内容

<div className="field-table">

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `data_type` | `string` | 必填 | 固定为 `PaymentBulkSendItemUpdate`。 |
| `bulk_send_item_id` | `string` | 必填 | 条目 ID，也是对账使用的键。 |
| `bulk_send_id` | `string` | 必填 | 该条目所属的批次 ID。 |
| `request_id` | `string` | 选填 | 批次的请求 ID，同一批次下所有条目相同。逐条幂等请用 `bulk_send_item_id`。 |
| `source_account` | `string` | 必填 | 批次的付款账户。 |
| `status` | `string` | 必填 | 该条目的当前状态，含义见[条目的事件触发条件](#条目的事件触发条件)：<br/>• `Pending`<br/>• `Processing`<br/>• `Completed`<br/>• `Failed`<br/>• `NotExecuted` |
| `requested_amount` | `object` | 必填 | 该条目的请求下发金额。条目整体成功或整体失败，因此没有单独的已完成金额和失败金额。 |
| `requested_amount.amount` | `string` | 必填 | 金额，十进制字符串。 |
| `requested_amount.token_id` | `string` | 必填 | 币种 ID。 |
| `requested_amount.chain_id` | `string` | 必填 | 链 ID。 |
| `receiving_address` | `string` | 必填 | 收款方地址。 |
| `tx_hash` | `string` | 必填 | 该条目转出交易的链上哈希。尚未广播时为 `null`；失败时为 `null` 表示从未上链，有值表示已上链但失败。 |
| `description` | `string` | 必填 | 您创建该条目时填写的备注，未填写时为 `null`。 |
| `failed_reason` | `object` | 必填 | `status` 为 `Failed` 或 `NotExecuted` 时有值，其余情况为 `null`。 |
| `failed_reason.code` | `string` | 必填 | 失败原因代码，按它分支。取值见[条目的失败原因](#条目的失败原因)。 |
| `failed_reason.message` | `string` | 必填 | 面向运营人员的说明，不要用于程序匹配。 |
| `created_timestamp` | `integer` | 必填 | 该条目的创建时间，Unix 时间戳（秒）。 |
| `updated_timestamp` | `integer` | 必填 | 该条目最近一次状态更新时间，Unix 时间戳（秒）。 |

</div>

### 条目的失败原因

`failed_reason.code` 是您分支的依据。下面是条目可能携带的 code。

| `code` | 发生了什么 | 怎么处理 |
| --- | --- | --- |
| `payment.bulk_send_invalid_address` | 收款地址不合法，`message` 中包含该地址。 | 修正后在新批次中重发该条目。 |
| `payment.receiving_address_matches_source_address` | 收款地址与付款地址相同。 | 修正后在新批次中重发该条目。 |
| `payment.address_kya_failed` | 收款地址未通过 KYA 筛查，`message` 中包含该地址。 | 不要再向该地址发送。 |
| `payment.strict_mode_other_items_validation_failed` | 该条目本身没有问题。`Strict` 模式下有别的条目未通过校验。 | 修正那个条目后重发本条目。 |
| `payment.strict_mode_other_sweep_tasks_failed` | 该条目本身没有问题。`Strict` 模式下有别的归集失败。 | 在新批次中重发。 |
| `payment.strict_mode_other_items_commission_fee_failed` | 该条目本身没有问题。`Strict` 模式下有别的条目佣金扣收失败。 | 处理 Fee Station 后重发。 |
| `payment.bulk_send_commission_fee_charge_failed` | Fee Station 余额不足。 | 充值后重发。 |
| `payment.bulk_send_commission_fee_station_not_configured` | 未配置 Fee Station。 | 配置后重发。 |
| `payment.bulk_send_commission_fee_charge_failed_unknown` | 佣金因其他原因扣收失败。 | 检查 Fee Station 的配置与余额，然后重发。 |
| `payment.app_workflow_approval_rejected` | 审批流拒绝了该批次。 | 向审批人确认原因，然后重发。 |
| `payment.app_workflow_approval_revoked` | 审批流被撤销。 | 让批次通过审批，然后重发。 |
| `transaction.rejected_by_policy` | 这笔转账命中了您自己配置的交易策略。 | 在 Cobo Portal 中调整该策略，然后重发。 |
| `transaction.rejected_by_approval` | 这笔转账在您组织的审批环节被拒绝——审批人拒绝，或您的回调服务器拒绝。 | 向对方确认原因，然后重发。 |
| `transaction.rejected_by_signer` | 这笔转账在签名环节被拒绝——co-signer 拒绝签名。 | 向 co-signer 确认原因，然后重发。 |
| `transaction.rejected_by_screening_app` | 您的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔转账。 | 到该应用查看原因，然后重发。 |
| `payment.sweep_task_failed` | 准备资金的归集交易失败。 | 重发。 |
| `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔转账。 | 不要重试，联系 Cobo。 |
| `payment.batch_payouts_execution_failed` | 转账失败且原因无法归类。 | 不要重试，联系 Cobo。 |
| `transaction.failed` | 原因无法归类。 | 不要重试，联系 Cobo 并提供 `bulk_send_item_id`。 |

### 条目的示例事件

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

#### 某个条目完成

```json
  "source_account": "developer",
  "status": "Completed",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "receiving_address": "0xaffiliate001",
  "tx_hash": "0xbulkitem001",
  "description": "affiliate 001",
  "failed_reason": null,
  "created_timestamp": 1744712000,
  "updated_timestamp": 1744712900
}
```

#### 某个条目在提交转账后失败

资金曾被锁定，现已释放，手续费已退回。能否原样重发取决于 `failed_reason.code`。

```json
{
  "data_type": "PaymentBulkSendItemUpdate",
```
