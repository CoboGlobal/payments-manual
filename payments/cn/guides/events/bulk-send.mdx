批量下发有两级事件：一级是批次，一级是批次里的每个条目。只需要批次结论就订阅批次事件，需要逐条对账就订阅条目事件。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

## `payment.bulk_send.updated`

批次级事件，以 `bulk_send_id` 标识。

| `status` | 您该做什么 |
| --- | --- |
| `Pending` | 记录该批次并等待。批次停在这里可能有两种原因，参见 [`Pending` 可能是在等审批](#pending-可能是在等审批)。 |
| `Validating` | 等待。此时还不知道哪些条目会被拒。 |
| `Transferring` | 等待。逐条进度来自条目事件。 |
| `Completed` | 关闭批次汇总。条目的完成仍以条目事件为准。 |
| `PartiallyCompleted` | 按两个计数分流处理：`failed_item_count` 是资金已经动过的条目，`not_executed_item_count` 是从未提交过的条目。 |
| `Failed` | 读取 `failed_reason`。整批失败只发生在**执行开始之前**。 |

### `Pending` 可能是在等审批

如果您的组织启用了审批流，新建批次会先进入审批。**审批过程不产生任何事件，也没有字段能区分。** 停在 `Pending` 的批次既可能在等待校验，也可能在等人审批，payload 看起来完全一样。长时间停在 `Pending` 不一定意味着卡住了。

### 事件内容

始终提供：`bulk_send_id`、`source_account`、`execution_mode`、`status`、`item_count`、`failed_item_count`、`not_executed_item_count`、`requested_amounts`、`completed_amounts`、`failed_amounts`、`description`、`commission_fees`、`created_timestamp`、`updated_timestamp`。您创建时提供了 `request_id` 的话，该字段也会出现。

| 字段 | 说明 |
| --- | --- |
| `bulk_send_id` | 批次身份。 |
| `source_account` | 批次的付款账户。 |
| `execution_mode` | 单个条目出问题是否中止整批。`Strict` 模式下会中止。 |
| `item_count` | 批次包含多少个条目。 |
| `failed_item_count` | 已提交且失败的条目数，这些条目的资金动过。 |
| `not_executed_item_count` | 从未提交的条目数，这些条目的资金没有动过。 |
| `requested_amounts` | 请求总额，按 token 分组。一个批次可以跨多种 token 和多条链。 |
| `completed_amounts` | 已完成条目的合计，按 token 分组。 |
| `failed_amounts` | 未成功条目的合计，按 token 分组。 |
| `description` | 批次备注。 |
| `commission_fees` | Cobo 收取的佣金，每个 token 一条。 |
| `failed_reason` | 当 `status` 为 `Failed` 时出现。 |

`failed_amounts` 把两类未成功条目——资金动过的和从未提交的——合并成每个 token 一个数。要区分它们，请使用 `failed_item_count` 与 `not_executed_item_count`，或查看条目事件。

批次事件**不携带条目列表**。逐条信息只通过条目事件送达，且两者的到达顺序不作保证。

### 失败 code

`failed_reason.code` 是您分支的依据。整批失败只发生在执行开始之前，因此下面这些都意味着没有资金动过。

**修正条目后创建新批次**

| `code` | 发生了什么 |
| --- | --- |
| `payment.bulk_send_no_valid_items` | 没有任何条目通过校验。 |
| `payment.bulk_send_strict_validation_failed` | `execution_mode` 为 `Strict` 且有条目未通过校验，批次因此中止。 |
| `payment.bulk_send_all_items_failed` | 所有条目都失败或从未执行。逐条原因在条目事件中。 |

**Fee Station 扣不出来——处理掉之后创建新批次**

| `code` | 发生了什么 |
| --- | --- |
| `payment.bulk_send_commission_fee_all_failed` | 所有条目的佣金都未能扣收。 |
| `payment.bulk_send_strict_commission_fee_failed` | `execution_mode` 为 `Strict` 且有条目的佣金扣收失败。 |

**没有需要修正的，直接创建新批次**

| `code` | 发生了什么 |
| --- | --- |
| `payment.bulk_send_strict_sweep_failed` | `execution_mode` 为 `Strict` 且有归集交易失败。 |

批次也可能因为审批被拒绝或被撤销而失败，该原因汇报在条目上。

## `payment.bulk_send.item.updated`

条目级事件，以 `bulk_send_item_id` 标识。

| `status` | 是否终态 | 您该做什么 |
| --- | --- | --- |
| `Pending` | 否 | 建立条目记录。这个值覆盖**两个阶段**：等待校验，以及校验通过但尚未提交转出。 |
| `Processing` | 否 | 转出已提交，等待结果。 |
| `Completed` | 是 | 保存金额和 `tx_hash`，关闭该条目。 |
| `Failed` | 是 | 转出已提交但失败。锁定资金已释放、手续费已退回。能否原样重发取决于 `failed_reason.code`。 |
| `NotExecuted` | 是 | 条目从未提交，**资金完全没有动过**。读取 `failed_reason.code`：不修正原因就重发会再次失败。 |

`Failed` 与 `NotExecuted` 的区别在于钱有没有动过，两者需要分开处理。

### 事件内容

始终提供：`bulk_send_item_id`、`bulk_send_id`、`status`、`requested_amount`、`receiving_address`、`tx_hash`、`source_account`、`description`、`created_timestamp`、`updated_timestamp`。批次有 `request_id` 时该字段也会出现。

| 字段 | 说明 |
| --- | --- |
| `bulk_send_item_id` | 条目身份，也是您对账时使用的键。 |
| `bulk_send_id` | 该条目所属的批次。 |
| `requested_amount` | 请求下发的金额，资产金额结构。条目整体完成或整体失败，因此没有单独的已完成金额和失败金额。 |
| `receiving_address` | 收款方地址。 |
| `tx_hash` | 链上哈希。条目从未上链时没有该值。 |
| `description` | 条目备注。 |
| `failed_reason` | 当 `status` 为 `Failed` 或 `NotExecuted` 时出现。 |

### 失败 code

`failed_reason.code` 是您分支的依据。下面是条目可能携带的 code，按需要采取的处理方式分组。

**修正该条目后在新批次中重发**

| `code` | 发生了什么 |
| --- | --- |
| `payment.bulk_send_invalid_address` | 收款地址不合法，`message` 中包含该地址。 |
| `payment.receiving_address_matches_source_address` | 收款地址与付款地址相同。 |

**不要再向该地址发送**

| `code` | 发生了什么 |
| --- | --- |
| `payment.address_kya_failed` | 收款地址未通过 KYA 筛查，`message` 中包含该地址。 |

**该条目本身没有问题，是被同批其他条目连累**

| `code` | 发生了什么 |
| --- | --- |
| `payment.strict_mode_other_items_validation_failed` | `Strict` 模式下有别的条目未通过校验。请修正那个条目。 |
| `payment.strict_mode_other_sweep_tasks_failed` | `Strict` 模式下有别的归集失败。 |
| `payment.strict_mode_other_items_commission_fee_failed` | `Strict` 模式下有别的条目佣金扣收失败。请检查 Fee Station。 |

**Fee Station 扣不出来——处理掉之后重发**

| `code` | 发生了什么 |
| --- | --- |
| `payment.bulk_send_commission_fee_charge_failed` | Fee Station 余额不足。请充值。 |
| `payment.bulk_send_commission_fee_station_not_configured` | 未配置 Fee Station。请先配置。 |
| `payment.bulk_send_commission_fee_charge_failed_unknown` | 因其他原因扣收失败。请同时检查配置与余额。 |

**批次没有通过审批**

| `code` | 发生了什么 |
| --- | --- |
| `payment.app_workflow_approval_rejected` | 审批流拒绝了该批次。请向审批人确认原因。 |
| `payment.app_workflow_approval_revoked` | 审批流被撤销。 |

**您这边有人拒绝了这笔转账——处理掉之后重发**

| `code` | 发生了什么 |
| --- | --- |
| `transaction.rejected_by_policy` | 这笔转账命中了您自己配置的交易策略。请在 Cobo Portal 中调整该策略。 |
| `transaction.rejected_by_approval` | 您组织内的审批人拒绝了这笔转账。请联系该审批人。 |
| `transaction.rejected_by_screening_app` | 您的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔转账。请到该应用查看原因。 |

**没有需要修正的，直接重发**

| `code` | 发生了什么 |
| --- | --- |
| `payment.sweep_task_failed` | 准备资金的归集交易失败。 |

**不要重试，联系 Cobo**

| `code` | 发生了什么 |
| --- | --- |
| `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔转账。 |
| `payment.batch_payouts_execution_failed` | 转账失败且原因无法归类。 |
| `transaction.failed` | 原因无法归类。提交问题时请提供 `bulk_send_item_id`。 |

## 示例事件

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

### 批次已受理

记录批次，不要重复提交。注意 `Pending` 也可能表示批次在等审批。

```json
{
  "data_type": "PaymentBulkSendUpdate",
  "bulk_send_id": "bulk_001",
  "request_id": "request_bulk_001",
  "source_account": "developer",
  "execution_mode": "Loose",
  "status": "Pending",
  "item_count": 3,
  "failed_item_count": 0,
  "not_executed_item_count": 0,
  "requested_amounts": [
    { "amount": "300.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "completed_amounts": [],
  "failed_amounts": [],
  "description": "September affiliate payouts",
  "commission_fees": [],
  "created_timestamp": 1744710000,
  "updated_timestamp": 1744710000
}
```

### 批次完成

关闭批次汇总。各条目仍以自己的事件为准。

```json
{
  "data_type": "PaymentBulkSendUpdate",
  "bulk_send_id": "bulk_001",
  "request_id": "request_bulk_001",
  "source_account": "developer",
  "execution_mode": "Loose",
  "status": "Completed",
  "item_count": 3,
  "failed_item_count": 0,
  "not_executed_item_count": 0,
  "requested_amounts": [
    { "amount": "300.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "completed_amounts": [
    { "amount": "300.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "failed_amounts": [],
  "description": "September affiliate payouts",
  "commission_fees": [
    { "token_id": "ETH_USDC", "fee_amount": "0.60" }
  ],
  "created_timestamp": 1744710000,
  "updated_timestamp": 1744711200
}
```

### 批次部分完成

按两个计数分流处理。本例有一个条目资金动过并失败，另一个从未提交——`failed_amounts` 把两者合并成一个数，所以只能靠计数区分。

```json
{
  "data_type": "PaymentBulkSendUpdate",
  "bulk_send_id": "bulk_002",
  "request_id": "request_bulk_002",
  "source_account": "developer",
  "execution_mode": "Loose",
  "status": "PartiallyCompleted",
  "item_count": 3,
  "failed_item_count": 1,
  "not_executed_item_count": 1,
  "requested_amounts": [
    { "amount": "300.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "completed_amounts": [
    { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "failed_amounts": [
    { "amount": "200.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "description": "September affiliate payouts",
  "commission_fees": [
    { "token_id": "ETH_USDC", "fee_amount": "0.20" }
  ],
  "created_timestamp": 1744712000,
  "updated_timestamp": 1744713000
}
```

### Strict 模式在执行前中止了批次

没有资金动过。修正被指出的条目后创建新批次。具体是哪些条目有问题，来自条目事件。

```json
{
  "data_type": "PaymentBulkSendUpdate",
  "bulk_send_id": "bulk_003",
  "request_id": "request_bulk_003",
  "source_account": "developer",
  "execution_mode": "Strict",
  "status": "Failed",
  "item_count": 3,
  "failed_item_count": 0,
  "not_executed_item_count": 3,
  "requested_amounts": [
    { "amount": "300.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "completed_amounts": [],
  "failed_amounts": [
    { "amount": "300.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
  ],
  "description": "September affiliate payouts",
  "commission_fees": [],
  "failed_reason": {
    "code": "payment.bulk_send_strict_validation_failed",
    "message": "Cannot complete bulk send: one or more items failed validation when 'execution_mode' is 'Strict'."
  },
  "created_timestamp": 1744714000,
  "updated_timestamp": 1744714100
}
```

### 某个条目完成

保存金额和 `tx_hash`，并用 `bulk_send_item_id` 关联回您自己的收款人记录后关闭该条目。

```json
{
  "data_type": "PaymentBulkSendItemUpdate",
  "bulk_send_item_id": "bulk_item_0001",
  "bulk_send_id": "bulk_002",
  "request_id": "request_bulk_002",
  "source_account": "developer",
  "status": "Completed",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "receiving_address": "0xaffiliate001",
  "tx_hash": "0xbulkitem001",
  "description": "affiliate 001",
  "created_timestamp": 1744712000,
  "updated_timestamp": 1744712900
}
```

### 某个条目在提交转账后失败

资金动过又退回：锁定资金已释放、手续费已退回。能否原样重发取决于 `failed_reason.code`。

```json
{
  "data_type": "PaymentBulkSendItemUpdate",
  "bulk_send_item_id": "bulk_item_0002",
  "bulk_send_id": "bulk_002",
  "request_id": "request_bulk_002",
  "source_account": "developer",
  "status": "Failed",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "receiving_address": "0xaffiliate002",
  "tx_hash": null,
  "description": "affiliate 002",
  "failed_reason": {
    "code": "transaction.rejected_by_approval",
    "message": "An approver in your organization rejected this transaction. Contact them, then resend."
  },
  "created_timestamp": 1744712000,
  "updated_timestamp": 1744712950
}
```

### 某个条目从未执行

**没有资金动过。** 修正原因后再重发，否则会以同样的方式失败。本例条目自身没有问题，是 `Strict` 模式下被同批其他条目连累。

```json
{
  "data_type": "PaymentBulkSendItemUpdate",
  "bulk_send_item_id": "bulk_item_0003",
  "bulk_send_id": "bulk_003",
  "request_id": "request_bulk_003",
  "source_account": "developer",
  "status": "NotExecuted",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "receiving_address": "0xaffiliate003",
  "tx_hash": null,
  "description": "affiliate 003",
  "failed_reason": {
    "code": "payment.strict_mode_other_items_validation_failed",
    "message": "Cannot execute bulk send item: one or more other items failed validation when 'execution_mode' is 'Strict'."
  },
  "created_timestamp": 1744714000,
  "updated_timestamp": 1744714100
}
```

### 重发失败的条目

原批次和原条目上都没有重试。请创建新的批次，或为单个收款人创建一笔转出，并在自己的记录里保留原 `bulk_send_id` 与 `bulk_send_item_id`——新事件不携带指回它们的引用。

## 交易级细节

`payment.bulk_send.status.updated` 与 `payment.bulk_send.item.status.updated` 返回的是批次和条目底层的交易信息，说明见[交易级事件](/payments/cn/guides/events/transaction-level#对象的交易级事件)。
