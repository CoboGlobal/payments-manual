Cobo Payments 通过 Webhook 事件通知您的系统。本章按支付业务组织：找到与您业务对应的页面，该页面会列出这条链路所需的全部事件。

## 按支付业务选择事件

只订阅您实际使用的支付业务所对应的事件。每个页面覆盖该业务自己的事件，以及这条链路还需要的补充事件。

| 您的业务 | 事件 | 页面 |
| --- | --- | --- |
| 充值（付款方直接入金） | `payment.topup.updated` | [充值事件](/payments/cn/guides/events/top-up) |
| 收款订单（订单模式） | `payment.order.updated` | [订单事件](/payments/cn/guides/events/orders) |
| 退款 | `payment.refund.updated` | [退款事件](/payments/cn/guides/events/refunds) |
| 单笔资金转出与转账 | `payment.payout.updated` | [资金转出事件](/payments/cn/guides/events/payouts) |
| 批量下发 | `payment.bulk_send.updated`、`payment.bulk_send.item.updated` | [批量下发事件](/payments/cn/guides/events/bulk-send) |
| 账户余额 | `payment.account.balance.updated` | [余额变动](/payments/cn/guides/events/balances) |

**其余的支付事件都是高级事件。** 这既包括 `payment.transaction.*` 这一族，也包括 `*.status.updated` 这一族（`payment.order.status.updated`、`payment.refund.status.updated`、`payment.payout.status.updated`、`payment.bulk_send.status.updated`、`payment.bulk_send.item.status.updated`）：它们返回的都是底层链上交易的细节，只在您需要关心这些细节时才需要订阅，例如确认数、手续费明细，或替换（丢弃、重发、加速）情况。

每个业务页面会列出属于该链路的高级事件，[高级事件](/payments/cn/guides/events/advanced)则逐个说明，并收录共用的交易字段。

## 所有支付事件一览

不论您的接入是否需要，这里列出全部支付事件。如果您已经订阅了某个事件、想知道它写在哪，点它的链接。**「必选」的判据是：这是您知道这件事的唯一途径。** 标「否」的那些，同一个事实在别处也拿得到——它们只是在更低一层重复了一遍，多给了链上细节。必选仍然按业务划分：只做订单收款时，充值相关的几个用不上。

| 事件 | 必选 | 通知什么 |
| --- | --- | --- |
| [`payment.topup.updated`](/payments/cn/guides/events/top-up#paymenttopupupdated) | **是** | 一笔充值从被检测到、经过筛查，直到可以入账或者失败的全过程。能不能入账只看 `status`。 |
| [`payment.order.updated`](/payments/cn/guides/events/orders#paymentorderupdated) | **是** | 一笔订单的收款结果：已付清、到期少付、到期且无入账、某笔入金需要您处理，或者订单结束后又收到钱。 |
| [`payment.refund.updated`](/payments/cn/guides/events/refunds#paymentrefundupdated) | **是** | 一笔退款单：已创建待执行、已完成，或者失败且一分未退。退款不存在部分完成。 |
| [`payment.payout.updated`](/payments/cn/guides/events/payouts#paymentpayoutupdated) | **是** | 一笔资金转出：处理中、已完成、部分完成（有一笔金额需要重发）、失败，或者被收款银行拒绝。 |
| [`payment.bulk_send.updated`](/payments/cn/guides/events/bulk-send#paymentbulk_sendupdated) | **是** | 一个批次的结果，以及金额和数量汇总——包括资金动过后失败的条目数，与从未提交的条目数。 |
| [`payment.bulk_send.item.updated`](/payments/cn/guides/events/bulk-send#paymentbulk_senditemupdated) | **是** | 单个条目的结果，用于与您自己的收款人记录核销。它区分「已提交后失败」和「从未提交」。 |
| [`payment.address.updated`](/payments/cn/guides/events/top-up#paymentaddressupdated) | **是** | 某个付款方的入金地址被替换，同时给出替换前与替换后的地址。**Cobo 也会主动更换地址**，此时这是您唯一的通知来源。 |
| [`payment.transaction.external.created`](/payments/cn/guides/events/top-up#paymenttransactionexternal) | **是** | 收到一笔不属于任何入金计划、也不属于任何订单的入金，或者币种不受支持。它计入您的开发者余额，不计入付款方或订单。 |
| [`payment.transaction.external.completed`](/payments/cn/guides/events/top-up#paymenttransactionexternal) | **是** | 那笔意外入金通过了筛查，已计入您的开发者余额。 |
| [`payment.bank_withdrawal.status.updated`](/payments/cn/guides/events/payouts#paymentbank_withdrawalstatusupdated) | **是** | 从您的某个虚拟账户提现法币到银行账户的状态变更。它带的是 `timeline`，没有 `updated_timestamp`。 |
| [`payment.account.balance.updated`](/payments/cn/guides/events/balances#paymentaccountbalanceupdated) | **是** | 某个账户在某个 token 上的可用余额发生变动，给出变动前后的余额和变动来源。每个账户实际收到多少，看这个事件。 |
| [`payment.transaction.created`](/payments/cn/guides/events/advanced#入金交易) | 否 | 入金地址收到一笔新的入金，并给出背后的链上细节。仅充值模式。 |
| [`payment.transaction.completed`](/payments/cn/guides/events/advanced#入金交易) | 否 | 一笔入金通过筛查并已入账，附带确认数、手续费和区块信息。 |
| [`payment.transaction.failed`](/payments/cn/guides/events/advanced#入金交易) | 否 | 一笔入金未通过筛查，附带交易层面的细节。 |
| [`payment.transaction.late`](/payments/cn/guides/events/advanced#入金交易) | 否 | 订单进入终态后，又收到一笔通过筛查的入金。它与订单事件的 `LatePaymentReceived` 说的是同一件事。 |
| [`payment.order.status.updated`](/payments/cn/guides/events/advanced#paymentorderstatusupdated) | 否 | 订单的交易明细，包括 `transactions` 数组和费用字段。 |
| [`payment.refund.status.updated`](/payments/cn/guides/events/advanced#paymentrefundstatusupdated) | 否 | 退款的交易明细，包括 `transactions` 数组和费用字段。 |
| [`payment.payout.status.updated`](/payments/cn/guides/events/advanced#paymentpayoutstatusupdated) | 否 | 转出的交易明细，包括 `transactions` 数组和 `payout_items`。 |
| [`payment.bulk_send.status.updated`](/payments/cn/guides/events/advanced#paymentbulk_sendstatusupdated) | 否 | 批次的交易明细。 |
| [`payment.bulk_send.item.status.updated`](/payments/cn/guides/events/advanced#paymentbulk_senditemstatusupdated) | 否 | 条目的交易明细，包括 `validation_status`，以及拆成独立字段的 `token_id` 与 `amount`。 |

## 事件结构

所有 Webhook 消息共用同一个外层结构。先用 `type` 路由，再按 `data_type` 反序列化 `data`。

```json
{
  "event_id": "8f2e919a-6a7b-4a9b-8c1a-4c0b3f5b8b2f",
  "url": "https://example.com/webhook",
  "created_timestamp": 1701396866000,
  "type": "payment.topup.updated",
  "data": { "data_type": "PaymentTopUpUpdate" },
  "status": "Success"
}
```

| `type` | `data.data_type` | 业务单据 ID |
| --- | --- | --- |
| `payment.topup.updated` | `PaymentTopUpUpdate` | `transaction_id` |
| `payment.order.updated` | `PaymentOrderUpdate` | `order_id` |
| `payment.refund.updated` | `PaymentRefundUpdate` | `refund_id` |
| `payment.payout.updated` | `PaymentPayoutUpdate` | `payout_id` |
| `payment.bulk_send.updated` | `PaymentBulkSendUpdate` | `bulk_send_id` |
| `payment.bulk_send.item.updated` | `PaymentBulkSendItemUpdate` | `bulk_send_item_id` |

充值没有单独的 `topup_id`。它的对象 ID 就是 `transaction_id`，因为一笔充值本身就是一笔入账交易。

## 在两个层面做去重

| ID | 防的是什么 |
| --- | --- |
| `event_id` | 重复投递。同一条消息重投时 `event_id` 不变。 |
| 业务单据 ID | 同一个业务事实被不同事件或不同代码路径处理两次。 |

两层都要做。对 `event_id` 建唯一约束用于投递去重，再对每个不可逆动作（入账、发货、关闭付款）按业务单据 ID 建第二个唯一约束。

## 所有事件通用的规则

**按 `status` 分支。** 它是唯一供程序判断使用的字段。

- 不要自己比较金额来判断订单是否付清。订单足额判定带容差，自行比较会把 Cobo 认定已付清的订单判成没付够。
- 不要匹配 `message` 或 `failed_reason.message`。这些文本面向运营人员，措辞会变。
- 不要用链上确认数判断资金是否可用。确认数是否达标已经体现在 `status` 里。

**数组是全量快照。** `transactions` 等字段携带的是该对象当前的完整列表，不是自上条事件以来的增量。请整体替换本地副本，不要往里追加。

**投递不保证顺序。** 按业务单据 ID 做 upsert，并丢弃比本地已记录状态更早的事件。终态不能被后到的处理中事件回退。

**没有值的字段不会出现。** 字段不适用时，整个键会被省略而不是给 `null`。读取可选字段时请使用防御性写法，例如用 `payload.get("failed_reason")` 而不是 `payload["failed_reason"]`。

## 读取失败原因

可能汇报失败的事件会携带一个 `failed_reason` 对象。

```json
"failed_reason": { "code": "transaction.rejected_by_policy", "message": "..." }
```

`code` 是受控枚举，也是您分支的依据。请保留完整字符串，不要按点号拆开——前缀是取值的一部分，不是需要您解读的信息。

`message` 面向运营人员，措辞可能调整，因此可以展示但绝不能用于匹配。

每个业务页面会列出该对象上可能出现的 code，并按需要采取的处理方式分组：[充值](/payments/cn/guides/events/top-up#失败-code)、[订单](/payments/cn/guides/events/orders#失败-code)、[退款](/payments/cn/guides/events/refunds#失败-code)、[资金转出](/payments/cn/guides/events/payouts#失败-code)、[批量下发](/payments/cn/guides/events/bulk-send#批次的失败-code)。

### 提交问题时报业务单据 ID

需要排查失败时，请提供业务单据 ID 而不是交易 ID：充值用 `transaction_id`，其余用 `order_id`、`refund_id`、`payout_id`、`bulk_send_id`、`bulk_send_item_id`。每个 payload 都一定带自己的单据 ID，而交易 ID 在退款和批量下发条目的 payload 中根本不存在。

对于 Payout，一个 `payout_id` 下可能有多笔转出交易，因此只有单据 ID 才能追溯整个请求。

## 读取金额

所有金额都是十进制字符串而不是数字类型，请使用 decimal 类型解析。

| 结构 | 字段 | 用在哪 |
| --- | --- | --- |
| 资产金额 | `amount`、`token_id`、`chain_id` | 绝大多数金额字段。 |
| 资产或法币金额 | `amount_type`，以及 `amount` 加上 `token_id` 与 `chain_id`，或者 `currency` | 可能是加密货币也可能是法币的字段，例如 `actual_payout_amount`。请先读 `amount_type`，不要根据有没有 `token_id` 推断。 |
| 佣金 | `token_id`、`fee_amount` | Cobo 收取的佣金。 |

```json
{ "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" }
{ "amount_type": "Crypto", "amount": "300.00", "token_id": "TRON_USDT", "chain_id": "TRON" }
{ "amount_type": "Fiat", "amount": "497.50", "currency": "USD" }
{ "token_id": "ETH_USDC", "fee_amount": "2.50" }
```

字段名为复数的（例如 `requested_amounts`）是数组，可能跨多种 token；单数字段是单个对象，只涉及一种资产。不要跨资产相加。

Webhook 消息不携带余额和手续费明细，以保证您读到的数值不会因为并发活动而失真。要保持自己账本的实时性，请在收到事件时调用[List merchant balances](/payments/en/api-references/payment/list-merchant-balances)或[Get developer balances](/payments/en/api-references/payment/get-developer-balance)。需要手续费明细时，请使用交易查询接口或[Generate reports](/payments/en/api-references/payment/generate-reports)。
