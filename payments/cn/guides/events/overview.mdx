Cobo Payments 通过 Webhook 事件通知您的系统。本页列出 Cobo Payments 提供的全部事件，并按支付业务分组。点击事件名称可查看该事件的触发条件、字段说明和示例。

## 全部事件

事件分为两类：

- **标准事件**：各支付业务的结果通知，按您使用的业务订阅。
- **高级事件**：提供底层链上交易的细节，例如确认数、链上交易手续费和区块信息。同一业务结果已由标准事件通知，除非您需要这些细节，否则无需订阅。

## 事件结构

所有 Webhook 消息共用同一个外层结构。`event_id` 是事件的唯一标识，同一条事件重投时不变，可用于去重。

外层的 `created_timestamp` 是**这条事件的创建时间，单位毫秒**，重投时不变。事件的创建顺序不一定与业务状态变化的顺序一致，所以**不要用它判断事件先后**。`data` 里的 `created_timestamp` 与 `updated_timestamp` 是**业务对象自己的创建与最近更新时间，单位秒**。

外层的 `status`（`Success`、`Retrying`、`Failed`）以及重试时才出现的 `next_retry_timestamp`、`retries_left` 描述的是这条消息的投递情况，与业务无关，处理时可以忽略。

```json
{
  "event_id": "8f2e919a-6a7b-4a9b-8c1a-4c0b3f5b8b2f",
  "url": "https://example.com/webhook",
  "created_timestamp": 1701396866000,
  "type": "payment.topup.updated",
  "data": {
    "data_type": "PaymentTopUpUpdate",
    ...
    "created_timestamp": 1701396800,
    "updated_timestamp": 1701396865
  },
  "status": "Success"
}
```

| `type` | `data.data_type` | 业务单据 ID |
| --- | --- | --- |
| `payment.topup.updated` | `PaymentTopUpUpdate` | `transaction_id` |
| `payment.order.updated` | `PaymentOrderUpdate` | `order_id` |
| `payment.refund.updated` | `PaymentRefundUpdate` | `refund_id` |
| `payment.payout.updated` | `PaymentPayoutUpdate` | `payout_id` |
| `payment.bulk_send.updated` | `PaymentBulkSendUpdate` | `bulk_send_id` |
| `payment.bulk_send.item.updated` | `PaymentBulkSendItemUpdate` | `bulk_send_item_id` |

充值没有单独的 `topup_id`。它的对象 ID 就是 `transaction_id`，因为一笔充值本身就是一笔入账交易。

## 所有事件通用的规则

### 空值

字段表中的字段始终出现在 payload 里，不适用时为 `null`，空数组为 `[]`。标注「选填」或「仅……时出现」的字段除外。

### 失败原因

可能汇报失败的事件会携带一个 `failed_reason` 对象。

```json
"failed_reason": { "code": "transaction.rejected_by_policy", "message": "..." }
```

`code` 是受控枚举，请根据它决定如何处理。`message` 面向运营人员，措辞可能调整，因此可以展示但绝不能用于匹配。

每个业务页面会列出该对象上可能出现的 code，并按需要采取的处理方式分组：[充值](/payments/cn/guides/events/top-up#失败原因)、[订单](/payments/cn/guides/events/orders#失败原因)、[退款](/payments/cn/guides/events/refunds#失败原因)、[资金转出及提现](/payments/cn/guides/events/payouts#失败原因)、[批量下发](/payments/cn/guides/events/bulk-send#批次的失败原因)。

### 金额

**除特殊说明外，金额固定 2 位小数（多余位数截断，不四舍五入），去掉尾零**（`100.00` 输出 `100`）。

| 结构 | 示例 | 用在哪 |
| --- | --- | --- |
| 资产金额 | `{ "amount": "100", "token_id": "ETH_USDC", "chain_id": "ETH" }` | 绝大多数金额字段。 |
| 资产或法币金额 | `{ "amount_type": "Crypto", "amount": "300", "token_id": "TRON_USDT", "chain_id": "TRON" }`<br/>`{ "amount_type": "Fiat", "amount": "497.5", "currency": "USD" }` | 可能是加密货币也可能是法币的字段，例如 `actual_payout_amounts` 的元素。用 `amount_type` 判断是哪一种。 |
| 佣金 | `{ "fee_amount": "2.5" }` | Cobo 收取的佣金，**单位为美元**。佣金从 Fee Station 扣，余额是美元口径。 |

字段名为复数的（例如 `requested_amounts`）是数组，可能跨多种 token；单数字段是单个对象，只涉及一种资产。不要跨资产相加。数组按 `token_id` 分组，同一种币在两条链上是两项。
