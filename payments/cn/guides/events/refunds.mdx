本页的事件跟踪一笔退款单从创建到完成的全过程。请先阅读[事件概述](/payments/cn/guides/events/overview)了解外层结构、去重方式以及所有事件通用的规则。

退款目前只支持订单。要退回通过充值模式收到的资金，请改为创建 Payout。

## 本页的事件

| 事件 | 通知什么 | 什么时候需要订阅 |
| --- | --- | --- |
| [`payment.refund.updated`](#paymentrefundupdated) | 一笔退款单的结果：已创建、已完成，或者失败且一分未退。 | 必选——这是退款业务的事件。 |

## `payment.refund.updated`

退款的主事件，以 `refund_id` 标识。

| `status` | 触发时机 | 您该做什么 |
| --- | --- | --- |
| `Pending` | 通过退款链接成功创建退款单。 | 记录该退款单并等待。 |
| `Completed` | 退款完成。 | 对账并关闭退款，以 `refund_id` 作为幂等键。 |
| `Failed` | 退款失败，**一分未退**。 | 读取 `failed_reason` 并处理。 |

只有这三个值会送达您。公开的 `RefundStatus` 枚举还包含 `PendingConfirmation`、`AddressPending`、`AddressSubmitted`、`Processing`、`PartiallyCompleted`，但它们都没有对应的发送点，不会出现在任何事件中。您的 SDK 里仍会有这些枚举值，但不需要为它们编写分支。

一笔退款要么全额成功，要么全额失败，不存在部分退款的结果。

### 事件内容

始终提供：`refund_id`、`order_id`、`merchant_id`、`request_id`、`to_address`、`status`、`requested_amount`、`tx_hash`、`refund_type`、`initiator`、`commission_fee`、`created_timestamp`、`updated_timestamp`。

| 字段 | 说明 |
| --- | --- |
| `refund_id` | 退款单身份，也是您做对账幂等时使用的键。 |
| `order_id` | 本次退款所对应的收款订单。 |
| `request_id` | 您创建退款时提供的请求 ID。 |
| `to_address` | 接收退款的地址。 |
| `requested_amount` | 请求退还的金额，资产金额结构。对应您创建退款时传入的 `payable_amount`。 |
| `tx_hash` | 退款转账的链上哈希。退款在广播前就失败时没有该值。 |
| `refund_type` | 退款资金来自哪个余额，取 `Merchant` 或 `Psp`。 |
| `initiator` | 退款发起人。 |
| `commission_fee` | Cobo 收取的佣金，单个对象，包含 `token_id` 与 `fee_amount`。一笔退款只涉及一个 token，因此这里不是数组。收取后被全额冲回时该值可能为 `0`，冲回大于收取时可能为负数。 |
| `failed_reason` | 仅当 `status` 为 `Failed` 时出现，包含 `code` 与 `message`。 |

退款没有单独的已完成金额和失败金额字段，因此 `requested_amount` 既是请求退还的金额，也是 `status` 为 `Completed` 后实际退还的金额。

### 失败 code

`failed_reason.code` 是您分支的依据。

| `code` | 发生了什么 | 怎么处理 |
| --- | --- | --- |
| `transaction.rejected_by_policy` | 这笔转账命中了您自己配置的交易策略。 | 在 Cobo Portal 中调整该策略，然后重新创建退款。 |
| `transaction.rejected_by_approval` | 您组织内有人拒绝了这笔转账——可能是审批人，也可能是 co-signer 拒绝为它签名。 | 联系对方，然后重新创建退款。 |
| `transaction.rejected_by_screening_app` | 您的合规团队在 [Screening App](https://manuals.cobo.com/cn/apps/screening/introduction) 中拒绝了这笔转账。 | 到该应用查看原因，然后重新创建退款。 |
| `payment.refund_fee_charge_failed` | Fee Station 余额不足。 | 充值后重新创建退款。 |
| `payment.refund_fee_station_not_configured` | 未配置 Fee Station。 | 配置后重新创建退款。 |
| `payment.refund_fee_charge_failed_unknown` | 手续费因其他原因扣收失败。 | 检查 Fee Station 的配置与余额，然后重新创建退款。 |
| `payment.refund_sweep_failed` | 准备资金的归集交易失败。 | 重新创建退款。 |
| `payment.refund_transactions_failed` | 全部退款交易均失败。逐笔原因在 `payment.refund.status.updated` 中。 | 先看那里的明细再重试。 |
| `transaction.rejected_by_compliance` | Cobo 的合规检查拒绝了这笔转账。 | 不要重试，联系 Cobo。 |
| `transaction.failed` | 原因无法归类。 | 不要重试，联系 Cobo 并提供 `refund_id`。 |

### 示例

以下示例只展示 `data` 对象。外层结构所有事件都一样，参见[事件结构](/payments/cn/guides/events/overview#事件结构)。

#### 退款单已创建

记录并等待。不要为同一笔订单重复创建退款。

```json
{
  "data_type": "PaymentRefundUpdate",
  "refund_id": "refund_001",
  "order_id": "order_001",
  "merchant_id": "M1001",
  "request_id": "request_refund_001",
  "to_address": "0x9876543210abcdef1234567890abcdef12345678",
  "status": "Pending",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": null,
  "refund_type": "Merchant",
  "initiator": "api_key_abc123",
  "commission_fee": null,
  "created_timestamp": 1744690400,
  "updated_timestamp": 1744690400
}
```

#### 退款完成

对账并关闭，以 `refund_id` 作为幂等键。`requested_amount` 同时也是实际退还的金额。

```json
{
  "data_type": "PaymentRefundUpdate",
  "refund_id": "refund_001",
  "order_id": "order_001",
  "merchant_id": "M1001",
  "request_id": "request_refund_001",
  "to_address": "0x9876543210abcdef1234567890abcdef12345678",
  "status": "Completed",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": "0xrefund001",
  "refund_type": "Merchant",
  "initiator": "api_key_abc123",
  "commission_fee": { "token_id": "ETH_USDC", "fee_amount": "0.50" },
  "created_timestamp": 1744690400,
  "updated_timestamp": 1744690500
}
```

#### 退款失败

**一分未退。** 本例转账从未上链，因此 `tx_hash` 为空。

```json
{
  "data_type": "PaymentRefundUpdate",
  "refund_id": "refund_002",
  "order_id": "order_001",
  "merchant_id": "M1001",
  "request_id": "request_refund_002",
  "to_address": "0x9876543210abcdef1234567890abcdef12345678",
  "status": "Failed",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": null,
  "refund_type": "Merchant",
  "initiator": "api_key_abc123",
  "commission_fee": null,
  "failed_reason": {
    "code": "transaction.rejected_by_policy",
    "message": "This transaction was rejected by one of your transaction policies. Adjust the relevant policy in Cobo Portal, then resend."
  },
  "created_timestamp": 1744690600,
  "updated_timestamp": 1744690700
}
```

#### 退款在转账之前就失败

手续费无法扣收。向 Fee Station 充值后重新创建退款。

```json
{
  "data_type": "PaymentRefundUpdate",
  "refund_id": "refund_003",
  "order_id": "order_001",
  "merchant_id": "M1001",
  "request_id": "request_refund_003",
  "to_address": "0x9876543210abcdef1234567890abcdef12345678",
  "status": "Failed",
  "requested_amount": { "amount": "100.00", "token_id": "ETH_USDC", "chain_id": "ETH" },
  "tx_hash": null,
  "refund_type": "Merchant",
  "initiator": "api_key_abc123",
  "commission_fee": null,
  "failed_reason": {
    "code": "payment.refund_fee_charge_failed",
    "message": "Cannot charge refund fee: Fee Station balance is insufficient. Please add funds to Fee Station and try again."
  },
  "created_timestamp": 1744690800,
  "updated_timestamp": 1744690900
}
```
