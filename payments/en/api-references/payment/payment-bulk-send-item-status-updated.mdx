This webhook event is triggered when the status of a bulk send item changes.
Use it to track item-level execution results for a bulk send, especially when a
batch completes partially or individual items fail validation or transfer.

To test delivery to your registered Payments webhook endpoints, use
[Trigger test webhook event](/payments/en/api-references/payment/trigger-test-webhook-event)
with `event_type` set to `payment.bulk_send.item.status.updated`.

## Event type

`payment.bulk_send.item.status.updated`

## Event data schema

The `data` object uses the `PaymentBulkSendItemEvent` schema. It includes
`data_type: "PaymentBulkSendItem"`, the fields from `PaymentBulkSendItem`, and
the bulk-send context fields listed below.

| Field | Type | Required | Description |
| :---- | :--- | :------- | :---------- |
| `data_type` | string | Yes | The event data discriminator. Value: `PaymentBulkSendItem`. |
| `bulk_send_item_id` | string | Yes | The bulk send item ID. |
| `bulk_send_id` | string | Yes | The bulk send ID that this item belongs to. |
| `request_id` | string | No | The request ID of the bulk send batch. |
| `source_account` | string | Yes | The source account ID of the bulk send batch. |
| `token_id` | string | Yes | The token ID of the cryptocurrency sent to the recipient. |
| `receiving_address` | string | Yes | The recipient's cryptocurrency address. |
| `amount` | string | Yes | The cryptocurrency amount sent to the recipient. |
| `description` | string | No | A note or comment about the bulk send item. |
| `tx_hash` | string | No | The transaction hash of the bulk send item. |
| `status` | string | Yes | The item execution status. Possible values: `Pending`, `Processing`, `Completed`, `Failed`, `NotExecuted`. |
| `validation_status` | string | Yes | The item validation status. Possible values: `Pending`, `Validated`, `ValidationFailed`, `NotExecuted`. |
| `failed_reason` | string | No | The reason why the bulk send item failed. |
| `created_timestamp` | integer | Yes | The time when the bulk send item was created, represented as a Unix timestamp in seconds. |
| `updated_timestamp` | integer | Yes | The time when the bulk send item was last updated, represented as a Unix timestamp in seconds. |
