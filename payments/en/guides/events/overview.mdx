Cobo Payments notifies your system through webhook events. This page lists every event Cobo Payments provides, grouped by payment business. Click an event name to see its trigger conditions, fields, and samples.

## All events

Events come in two kinds:

- **Standard events** report the outcome of each payment business. Subscribe to the ones for the businesses you use.
- **Advanced events** provide detail about the underlying on-chain transactions, such as confirmations, on-chain transaction fees, and block information. The business outcome is already reported by a standard event, so you do not need to subscribe to these unless you need that detail.

## Event structure

Every webhook message shares the same envelope. `event_id` uniquely identifies an event and stays the same when the event is redelivered, so use it to deduplicate.

The envelope's `created_timestamp` is **when this event was created, in milliseconds**; it does not change on retries. Events are not necessarily created in the order the business state changed, so **do not use it to order them**. The `created_timestamp` and `updated_timestamp` inside `data` are **the business object's own creation and last-update times, in seconds**.

The envelope's `status` (`Success`, `Retrying`, `Failed`) and the `next_retry_timestamp` and `retries_left` fields that appear during retries describe delivery of this message, not your business, and can be ignored when processing.

```json
{
  "event_id": "8f2e919a-6a7b-4a9b-8c1a-4c0b3f5b8b2f",
  "url": "https://example.com/webhook",
  "created_timestamp": 1701396866000,
  "type": "payment.topup.updated",
  "data": {
    "data_type": "PaymentTopUpUpdate",
    ...
    "created_timestamp": 1701396800,
    "updated_timestamp": 1701396865
  },
  "status": "Success"
}
```

| `type` | `data.data_type` | Business record ID |
| --- | --- | --- |
| `payment.topup.updated` | `PaymentTopUpUpdate` | `transaction_id` |
| `payment.order.updated` | `PaymentOrderUpdate` | `order_id` |
| `payment.refund.updated` | `PaymentRefundUpdate` | `refund_id` |
| `payment.payout.updated` | `PaymentPayoutUpdate` | `payout_id` |
| `payment.bulk_send.updated` | `PaymentBulkSendUpdate` | `bulk_send_id` |
| `payment.bulk_send.item.updated` | `PaymentBulkSendItemUpdate` | `bulk_send_item_id` |

A top-up has no separate `topup_id`. Its record ID is `transaction_id`, because one top-up is one deposit transaction.

## Rules that apply to every event

### Empty values

Every field in the field tables is always present in the payload: `null` when it does not apply, `[]` for an empty array. Fields marked Optional or "Present only when…" are the exception.

### Failure reasons

Events that can report a failure carry a `failed_reason` object.

```json
"failed_reason": { "code": "transaction.rejected_by_policy", "message": "..." }
```

`code` is a controlled enumeration. Use it to decide how to handle the failure. `message` is written for human operators and its wording can change, so display it but never match on it.

Each business page lists the codes that can appear on that object, grouped by the response they need: [Top-up](/payments/en/guides/events/top-up#failure-reasons), [Order](/payments/en/guides/events/orders#failure-reasons), [Refund](/payments/en/guides/events/refunds#failure-reasons), [Payouts and withdrawals](/payments/en/guides/events/payouts#failure-reasons), [Bulk send](/payments/en/guides/events/bulk-send#batch-failure-reasons).

### Amounts

**Unless stated otherwise, amounts carry at most two decimal places, with trailing zeros stripped** (`100.00` is sent as `100`).

| Shape | Example | Where it is used |
| --- | --- | --- |
| Asset amount | `{ "amount": "100", "token_id": "ETH_USDC", "chain_id": "ETH" }` | Most amount fields. |
| Asset or fiat amount | `{ "amount_type": "Crypto", "amount": "300", "token_id": "TRON_USDT", "chain_id": "TRON" }`<br/>`{ "amount_type": "Fiat", "amount": "497.5", "currency": "USD" }` | Fields that can be either crypto or fiat, such as the entries of `actual_payout_amounts`. Use `amount_type` to tell which. |
| Commission fee | `{ "fee_amount": "2.5" }` | Commission charged by Cobo, **denominated in USD**. It is taken from Fee Station, whose balance is in USD. |

A field whose name is plural, such as `requested_amounts`, is an array and can span several tokens. A singular field is a single object covering one asset. Never add amounts across assets. Arrays group by `token_id`, so the same token symbol on two chains is two entries.
